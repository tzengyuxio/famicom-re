# FC 三國志 戰爭地圖

本文的位址除特別註明外都是 **PRG 位址**（檔案位址 − 0x10）；`$xxxx` 是 CPU 位址。

```bash
# 58 張戰爭地圖 → sangokushi/output/battle_maps/NN_州名.png（另有 terrain.png 地形一覽）
.venv/bin/python sangokushi/export_battle_maps.py [--rom ROM] [--out DIR] [--scale N]
# 用模擬器跑遊戲本身的程式，和靜態解碼比對（需要 py65，約 80 秒）
.venv/bin/python sangokushi/tools/verify_battle_maps.py [--provinces 5,1,10,26,58]
```

## 1. 地圖資料

| 項目 | 位址 | 說明 |
|------|------|------|
| 地圖 | `0x259A4`（bank 9 `$99A4`） | 58 張 × 168 bytes，國 1–58 依序，剛好到 `0x27FB4`（之後是 `FF`） |
| 大小 | | 14 欄 × 12 列，逐列存放 |
| 格子 | | 4 × 4 tile（32 × 32 px）。奇數欄往下錯半格（2 tile），排成六角格 |
| 地形 tile 排列 | `0xF574`（bank 3 `$B574`） | 每種地形 16 個 tile 編號（4×4 逐列），地形 0–5 |
| 地形 tile 圖形 | `0xF004`（bank 3 `$B004`） | 87 個 tile，載入 PPU `$1640`（背景 pattern table `$1000` 的 tile `$64–$BA`） |
| 背景調色盤 | `0x7C66`（bank 1 `$BC66`） | `3E 11 21 30 / 3E 29 39 30 / 3E 1C 29 30 / 3E 27 21 30` |
| 地形 → 子調色盤 | `0x7A5C`（bank 1 `$BA5C`） | `01 01 02 00 03 00` |

### 每格的 byte

| 位元 | 內容 |
|------|------|
| 3–5 | 地形 0–5 |
| 0–2 | 布陣區（見 §3） |
| 6–7 | ROM 裡都是 0。戰爭中城格會被設上 bit 7（遊戲執行時的旗標） |

| 地形 | 外觀 | 子調色盤 | 58 張合計 |
|------|------|----------|-----------|
| 0 | 平地 | 1 | 4368 格 |
| 1 | 山（綠） | 1 | 2295 |
| 2 | 森林／丘陵 | 2 | 232 |
| 3 | 河 | 0 | 1639 |
| 4 | 城 | 3 | 233 |
| 5 | 雪山（藍白） | 0 | 977 |

地形名稱是看圖判斷的，遊戲沒有顯示地形名稱。城在一張圖裡佔 1–8 格不等。

## 2. 遊戲怎麼讀（模擬器確認）

1. **選圖**：p-code 函式 `$EE79`（bank 15）算出 `($78A5 − $73A7) / 22 × 168 + $99A4`，再呼叫遠端複製 `$C248`，從 bank 9 複製 168 bytes 到 WRAM `$7B95`。`$73A7` 是 WRAM 的城市表（每筆 22 bytes，初始值在 `0x393AA`），`$78A5` 指向被攻打的國那一筆，所以第 n 國用第 n 張圖。
2. **畫格子**：p-code 讀 `$7B95` 的 byte，算 `(byte & $3F) >> 3 << 4 + $B574` 當來源，呼叫原生 `$C43D`（參數 `$52` nametable、`$54/$56` 左上、`$58/$5A` 右下、`$5C` 來源、`$5E` bank）畫 4×4 tile。欄 0–6 在 nametable 0 的 x = 4, 8 … 28，欄 7–13 在 nametable 1 的 x = 0 … 24；偶數欄 y = 4 + 4 × 列，奇數欄再加 2。畫面一次顯示 7 欄、約 7 列，其餘靠捲動。
3. **配色**：屬性表由 `$C729` 寫入，子調色盤查 `$BA5C` 表。

`tools/verify_battle_maps.py` 會在模擬器裡重播一段固定按鍵：劇本 1，曹操，從 7 國攻 5 國，打到「攻め込みますか」。地圖載入函式 `$EE79` 開始時，它把 `$78A5` 改指到要測的國，接著逐國比對：

- 複製到 `$7B95` 的 168 bytes 是否等於靜態解碼的那張圖（同時確認了索引公式）；
- 每個畫出的格子，來源 tile 排列和子調色盤是否等於靜態解碼；
- CHR-RAM 的 tile `$64–$BA` 與畫面淡入後的背景調色盤是否等於 ROM 資料。

預設測 5、1、10、26、58 國，地形 0–5 都有涵蓋，全部通過。故意把地圖起點錯開一張時，驗證會失敗（66 個錯誤）。

## 3. 布陣區（低 3 位元）

58 張圖全都使用 2、3、4、5 這四個值，跟相鄰國的數量無關。

- 布陣檢查是 p-code `$9930(cell, k)`：成立的條件是 `cell & 7` 等於 `k` 或 `k + 1`（另外會檢查 bit 5）。
- 攻方布陣時 `k = 2`，所以攻方能放的格子是 **2、3**。在模擬器裡把整張圖的低位元改成各個值再按 A 放置：值 2、3、6、7 都接受，0、1、4、5 顯示「ここには配置できません」。
- **4、5** 推定是守方布陣區：國 5 的 5 都圍在城旁邊，但守方的檢查沒有直接觀察到。
- 2 與 3、4 與 5 的差別（bit 0）不明。

## 4. 國與州

| 項目 | 位址 | 說明 |
|------|------|------|
| 國表 | `0x3B201`（bank 14 `$B201`） | 58 筆 × 14 bytes：`[x, y, ?, 國號, 州, 相鄰國 × 9（0 = 無）]`。相鄰關係雙向一致（280/280） |
| 州名 | `0x3B530`（bank 14 `$B530`） | 15 筆 × 12 bytes：`[假名 × 8, (漢字 tile, page) × 2]` |

本作的國只有編號，沒有名稱，所以檔名用 `NN_州名.png`。7 國 → 州 2「兗州」，和遊戲畫面上的「兗州 7こく」吻合。

## 5. 尚未解開

- 布陣值 bit 0（2 與 3、4 與 5）的意義；守方用 4、5 只是推定
- 戰爭中被改寫的格子：城格的 bit 7，以及改指目標國時 (0,0) 格的低位元被設成 6（可能是改指造成的副作用）
- 國表第 1–3 byte（x、y 看起來是戰略地圖上的位置，國 1 為 (0,0)、國 28 為 (3,7) 疑為例外；第 3 byte 不明）
- 只用一組 SCRIPT 打過一場真實戰爭，其他國是改指 `$78A5` 測的，部隊配置不一定和真實戰爭相同（不影響地形與配色的比對）

## 6. 工具

- `tools/nes_emu.py`：py65＋MMC1＋暫存器層級的 PPU（nametable、CHR-RAM、調色盤、OAM、vblank/NMI）＋控制器 1，可快照／還原狀態，可在指定 PC 設中斷回呼。
- 本作的按鍵：選單用上下＋A；數字輸入用上鍵加 1、右鍵乘 10，A 確定；Y/N 與 1/2 二選一用左＝Y/1、右＝N/2；B 看地圖。
- p-code 直譯器入口 `$F063`（跟水滸傳同一套，分派表 `$F866/$F966`）；原生函式經 BRK/IRQ 呼叫，參數放在 `$52–$65`。

## 7. 能否拼成一張全中國戰場：否定

檢驗的假設是：58 張戰場原本是同一張大圖切出來的，可以按國的相鄰關係拼回去。結論是**做不出可信的拼法，所以不匯出 `china_battle_map.png`**。

**遊戲本身不拼。** 地圖載入 `$EE79` 每場只複製一張（168 bytes → `$7B95`），沒有讀鄰國地圖的程式碼，ROM 裡也找不到各張地圖的位置或偏移表。如果真有拼法，只能從相鄰關係推出來。

**相鄰圖無法乾淨地嵌進六角格。**

- 國表（§4）共 140 條邊，雙向一致（280/280），紀錄 i 就是國 i+1，沒有解碼偏移。
- 以下 5 國超過 6 個鄰國，用國表 x,y 看，多出來的都是遠距離連結（例如 20↔37、21↔45、42↔51/55、29/32↔28）：

  | 國 | 鄰國數 | 鄰國 |
  |----|--------|------|
  | 20 | 8 | 5, 7, 13, 18, 19, 21, 37, 38 |
  | 21 | 8 | 15, 19, 20, 22, 23, 24, 38, 45 |
  | 29 | 7 | 10, 11, 12, 13, 28, 30, 32 |
  | 32 | 7 | 28, 29, 30, 31, 33, 34, 35 |
  | 42 | 7 | 39, 40, 41, 44, 46, 51, 55 |

  ROM 裡國只有編號、沒有名稱，所以無法確定這些是海路還是河路。
- 以 axial 座標做模擬退火（7 個種子），最好的結果只放得下 127/140 條邊。
- 放不下的 13 條：4–6、5–20、14–15、20–21、21–24、23–48、28–29、31–32、32–35、42–55、51–53、54–58、56–57。
- 國 28 的 x,y 是 (3,7)，落在揚州其他國（約 x 14–19）的另一頭，看起來是異常值。國 1 是 (0,0)。

**邊界接縫只比隨機好一點，遠不到連續的程度。**

做法：每張 14×12 圖放在嵌入的六角格位置，奇數列錯開半張圖寬（磚牆排法），旋轉、鏡像、列或行錯開共 24 種，取最好的一種。

| 指標 | 數值 |
|------|------|
| 相鄰兩圖交界處地形相同的比例 | 0.426（1177 個接觸） |
| 同樣挑 24 種中最好的，但先把地圖隨機打亂（40 次） | 中位數 0.344，最高 0.371 |
| 同一張圖內相鄰兩格相同（參考值） | 約 0.46–0.48 |
| 接縫上的河格對到河格 | 84/315 = 0.267（打亂：中位數 0.172，最高 0.243） |
| 同一張圖內河格接河格 | 0.500 |

- 接縫統計比隨機高。這可以由「相鄰的國地形組成相近」來解釋：北方多雪山，南方多河。
- 若真是一張大圖切開的，接縫應該和圖內一樣連續，河流尤其應該接得上。實際上河格只有約一半的圖內連續度。
- 只最大化接縫分數的話，可以把分數推到 0.53，但代價是相鄰關係只剩 84/140 條。這表示接縫分數和國的相鄰關係並不一致。

使用者記得的「戰場拼成全中國」是三國志II：41 張戰場依六角相鄰的直欄排法可以拼起來，見 `san2/docs/ROM_FORMAT.md`〈全中國戰場拼接測試〉。
