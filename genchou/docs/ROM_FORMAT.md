# FC 蒼き狼と白き牝鹿・元朝秘史 ROM 格式

KOEI，1992，FC。檔案 `roms/Aoki Ookami to Shiroki Mejika - Genchou Hishi (Japan).zip` 內的 `.nes`。

本文的偏移一律是 **PRG 偏移**（檔案偏移減 `0x10`），除非另外寫明「檔案偏移」。CPU 位址寫成 `$xxxx`。「bank n」指 8 KB 的 PRG bank，PRG 偏移 = `n × 0x2000`。

## 1. 硬體與程式

| 項目 | 內容 |
|------|------|
| iNES 標頭 | `4E 45 53 1A 20 20 52 …`：PRG 512 KB（64 × 8 KB）、CHR 256 KB（64 × 4 KB）、mapper 5（MMC5）、有電池 |
| 向量 | NMI `$F60C`、RESET `$F500`、IRQ `$FE9C` |
| RESET 的 bank 設定（`$F565`） | `$5113–$5117 = 04 FF FF FE FF`：`$8000`/`$A000`/`$E000` = bank 63，`$C000` = bank 62；WRAM 第 4 頁在 `$6000`。`$90+X` 存 `$5113+X` 的影子值，切 bank 的函式在 `$F99A` |
| 其他 MMC5 暫存器 | `$5100 = 3`（8 KB 模式）、`$5101 = 3`（1 KB CHR）、`$5102 = 2`、`$5103 = 1`、`$5104 = 1`（ExRAM 擴充屬性模式；NMI 寫 ExRAM 時暫時切成 2）、乘法器 `$5205/$5206`（`$F9D0`） |
| BG tile | ExRAM 擴充屬性模式：每個 BG tile 一個 ExRAM byte，bit 0–5 選 4 KB CHR bank，bit 6–7 選 4 色子調色盤。整份遊戲沒有寫 `$5128–$512B`（BG CHR 暫存器），只用 `$FAC0` 設精靈 bank `$5120–$5127` |
| 調色盤緩衝 | `$0701–$0720`（32 bytes，RESET 時填 `$0F`），`$FACE` 把資料複製進去 |
| bank 用途 | 0–3 劇本資料（開頭 `4C 00 00 00 FF`）；4–30 程式（多半映射在 `$A000`，少數在 `$8000`）；31、56、57 文字；32–37 戰場地圖；40–47、53、58 資料與圖；48–55 程式（`$A000`，開頭 `4C EE C0` 是殘樁）；62、63 固定的直譯器與系統程式 |

### 1.1 p-code 直譯器

跟其他 KOEI FC 作品一樣，大部分邏輯是 p-code。函式開頭 `JSR $DE22`，後面接 2 bytes 的 frame 大小，再接 bytecode。

| 項目 | 內容 |
|------|------|
| 暫存器 | A = `$08/09`、SP = `$02`、FP = `$04`、PC = `$06` |
| opcode 分派表 | 低位 `$E637`、高位 `$E737`，取指令在 `$DE68` |
| 常見 opcode | `$8A`/`$8C`/`$8E lo hi` 推 16 位元常數、`$8D xx`/`$8F xx` 推 8 位元、`$60–$6F` 推小常數、`$E9 lo hi n` 呼叫（n = 呼叫後要丟掉的參數 bytes）、`$D6`/`$D7`/`$D8 lo hi` 跳躍與條件跳躍、`$CF` 返回、`$A5 lo hi` 讀全域變數 |
| 系統呼叫 | `$E837`：參數從 p-code 堆疊複製到 `$50–$65`，**最後推入的值是服務編號**。常見：3 = 映射 bank（參數 1：槽位，0 = `$6000` 的 WRAM 頁、1 = `$8000`…；參數 2：選擇子，`$C0 + bank`）、6 = 設調色盤（資料、起點、長度）、9 = 畫圖（x、y、w、h、tile 指標、ExRAM 指標、選擇子；選擇子 `$FF` = RAM） |
| 遠程呼叫 | `push 參數…, push 位址, push 選擇子, push n, call $EDC5` |

模擬器 `tools/pcode_emu.py`（py65）可以直接呼叫 p-code 函式。等待 NMI 的迴圈（`$FBC4`、`$FBD1`、`$FC98`、`$FCAC`）會被模擬成 NMI。畫圖服務（9）要攔下來，讓它原生執行會卡在 NMI 與手把讀取的程式裡。

### 1.2 文字

cp932。漢字是原始 Shift-JIS；半形假名在預設模式（`ESC H` = `1B 48`）顯示成平假名，在 `ESC K`（`1B 4B`）之後顯示成片假名。`-` 是長音「ー」，`･` 是「・」。字串以 `00` 結尾。解碼在 `rom.text()`。

## 2. 劇本（bank 0–3）

| 劇本 | bank | 年（`+0x1499` LE16） | 國數（`+0x1496`） |
|------|------|------|------|
| 1 | 0 | 1184 | 14（モンゴル編） |
| 2 | 1 | 1206 | 33 |
| 3 | 2 | 1271 | 33 |
| 4 | 3 | 1185 | 33 |

劇本 4 的人物與劇本 2 大致相同，但年齡較小，例如耶律楚材是 −5 歲（`FB`），表示還沒出生。

### 2.1 人物（bank 偏移 5 起，109 格 × 26 bytes）

| 偏移 | 內容 |
|------|------|
| 0–15 | 姓名（§1.2 文字，`00` 補滿） |
| 16 | 王家（勢力）編號，`FF` = 在野；名稱見 §2.4 |
| 17 | 所在國編號（0 起算） |
| 18 | 體力：高 4 bits、低 4 bits（推定為最大值 / 現在值，劇本初始兩者相同） |
| 19 | 高 4 bits = 戦闘、低 4 bits = 政治（0 = E … 4 = A） |
| 20 | 高 4 bits = 魅力、低 4 bits = 指揮 |
| 21 | 年齡（有號數） |
| 22 | bit 2–4 = 文化：0 モンゴル、1 中央アジア、2 インド、3 日本、4 西欧、5 東欧、6 イスラム、7 中国（和每人所在國一致）。其他 bits 未知（`Unk22`） |
| 23 | 身分（推定）：3 = 王、1 = 家臣、0 = 在野；`80` = 空格 |
| 24–25 | 頭像碼 LE16（§3） |

格位排列：前面是各國的王與家臣，第 66 格起是在野。和外部資料（hishihishi 的 PC 版人物表）比對過ボオルチュ、ムカリ、ジェベ、スブタイ、オングル，能力一致；クビライ的魅力不同，可能是版本差異。

**劇本 1 的家族區**：bank 0 `0x149E` 起，同樣 26 bytes 一格：カサル、ベルグタイ、カチウン、テムゲ、ジェルメ、チンベ、チラウン，其後一格沒有姓名（頭像碼 `0018`）。`0x156E` 起的ジュチ等子女用的是另一種格式，`0x15F0` 起是另一組 8 格（タイチャル…），都還沒解。

### 2.2 國（bank 偏移 `0xB1A` 起，42 bytes × 國數）

| 偏移 | 內容 |
|------|------|
| 0 | 擁有的王家編號 |
| 1–2 | 金 LE16 |
| 3–4 | 食糧 LE16 |
| 5–6 | 人口 LE16 |
| 7–10 | 住民配分 %：農業、牧畜、特産、街（合計 100） |
| 11–14 | 4 個未知值，例：37 51 45 89（可能是農產力、經濟力、モラル、城防禦度一類） |
| 15–30 | 16 個小數字，**推定為各兵科的部隊數**（順序同 §4.1），例：モンゴル高原 = 軽歩兵 1、短弓兵 3、狩猟騎兵 2、蒙古騎兵 6 |
| 31–32 | 2 個未知值，例：90、100 |
| 33 | 旗標（0／16／32／64／128） |
| 34–37 | 第二組住民配分（推定為下令中的目標配分） |
| 38–41 | 未知 |

### 2.3 國名

| 表 | 偏移 | 格式 |
|----|------|------|
| モンゴル編 14 地域 | bank 57 `0x723A4` | 16 bytes × 14：オノン河流域、ケルレン河流域、興安嶺西麓、内モンゴル高原、ヤブロノイ山麓、ゴルゴナク河原、トーラ河流域、バイカル湖東岸、セレンゲ河流域、シベリア南部、バイカル湖西岸、ハンガイ山麓、エニセイ河上流、アルタイ山麓 |
| 世界 33 國 | bank 57 `0x725B4` | 16 bytes × 33：モンゴル高原 … イベリア |

### 2.4 王家名（bank 31）

`0x3E004 + 劇本 × 0x232 + 編號 × 17`，每格 17 bytes，空字串 = 沒有這個王家。第 0–3 組對應劇本 1–4，人物與國的王家編號都查這張表。第 4 組（`0x3E8CC`）是「モンゴル帝国、ナイマン帝国、ケレイト帝国…」，推定是モンゴル編統一後轉入世界編時用的名稱。

### 2.5 女性與子女

女性表在 bank 56（PRG `0x70004` 起，CPU `$A000` 起），每筆 17 bytes：`[姓名 15（§1.2 文字）][u16 頭像碼]`。一段以姓名第一個 byte 為 `00` 或 `20`（空白）的記錄結束。

各劇本的資料 bank（bank 0–3）載入 WRAM 時，bank 偏移 `0x1082`（另一份在 `0x116A`）是該劇本女性表的 CPU 指標，`0x0653` 是女兒名單的指標：

| PRG 偏移 | 指標 | 劇本 | 筆數 | 例 |
|------|------|------|------|------|
| `0x70004` | `$A004` | 1 | 14 | ボルテ P40、イェスイ P42、クラン P41、カルチュ 組合臉… |
| `0x70236` | `$A236` | 2 | 32 | 岐国公主 P75、八条 P54、イザベラ P58… |
| `0x70468` | `$A468` | 3 | 23 | 光明公主 P78、堀内 P55、テオドーラ P65… |
| `0x7069a` | `$A69A` | 4 | 23 | 北条政子 P56、ヤロスラブナ P67… |
| `0x708cc` | `$A8CC`（`0x0653`） | 2–4 | 287 | アラカイ、春姫、アンジェリーナ、光徳公主…（全部組合臉） |

- 劇本 1–3 的對應在模擬器開局後讀 WRAM 指標確認；劇本 4 在選單裡不出現，只有靜態確認（bank 3 的指標）。
- 專屬頭像 P40–P79 各對應一位女性，40 張都用到。另有部分女性用組合臉。4 段去重（姓名＋頭像碼）後 73 人。
- `0x708cc` 那段 287 筆（到 `0x71bdb`）是女兒名單：劇本 2–4 的 `0x0653` 指向它，劇本 1 是 0。推測是遊戲中出生的女兒依序取用的名字與臉，不是開局就有的人物。

子女表每筆 22 bytes：`[姓名 16][年齡][? ? ?][u16 頭像碼]`，每表 5 格，姓名第一個 byte 為 0 是空格：

| PRG 偏移 | 內容 |
|------|------|
| `0x156E`（bank 0） | ジュチ P35 |
| `0x1E0D4` | ジュチ P35 |
| `0x1E61C` | ジュチ 24 歲、チャガタイ P36、オゴタイ P37、トゥルイ P38 |
| `0x1F5F4` | ジュチ 3 歲、チャガタイ 1 歲 |

後三表在哪個劇本、何時載入，還沒確認。

## 3. 頭像

頭像一律是 5 × 6 tile（40 × 48），用主畫面 BG 調色盤（bank 52 `0x69338` = `$B338`：`0F273730 0F1B1627 0F2C2716 0F3C2C1B`，由 bank 52 `$A03F` 以服務 6 載入），ExRAM bit 6–7 選子調色盤。

分派函式在 bank 48 `$A684`（參數 x、y、頭像碼）：

- **bit 15 = 0**：專屬頭像，`$A660` 從 bank 46 畫第 `碼` 張（選擇子 `$EE`）。
- **bit 15 = 1**：組合臉，`$A49B` 映射 bank 41（選擇子 `$E9`），在 RAM 組好再畫。

### 3.1 專屬頭像（bank 46）

`0x5C004` 起 80 筆 × 60 bytes：30 個 tile 編號，再 30 個 ExRAM byte（列優先，5 欄）。人物表（§2.1）用到 P00–P34；P35–P38 是ジュチ、チャガタイ、オゴタイ、トゥルイ（子女表，見 §2.5），P40–P79 是女性（§2.5）。P39 是年輕男子，沒找到使用者。

### 3.2 組合臉（bank 41）

`0x52004` 起 86 筆 × 60 bytes（格式同 §3.1），每個「頭」兩筆：基本記錄 `2h`、替換記錄 `2h + 1`。

頭像碼：

| bits | 內容 |
|------|------|
| 15 | 1 = 組合臉 |
| 11–14 | 臉部程式不看（劇本 1 家族區有幾人設了 bit 11，畫出來和清掉 bit 11 一樣） |
| 8–10 | 文化 c：0 モンゴル、1 中国、2 中央アジア、3 インド、4 日本、5 イスラム、6 欧州 |
| 5–7 | 該文化中的第 n 個頭 |
| 4 | 上半（top） |
| 3 | 下半（body） |
| 2 | 眼 |
| 1 | 鼻 |
| 0 | 口 |

- 頭 h = `c × 6 + n`。n 為 6、7 時直接算進下一個文化（例：`80E8` 和 `8928` 都是頭 7），共 43 個頭（h = 0–42）。頭 42 只能由欧州 n = 6 得到（`86C0`–`86DF`），用到的都是欧州的女性（エウフェミア、クニグンダ…），所以算欧州的第 7 個頭；kaodata 的 label 是「文化／頭 n」，頭 42 寫成「欧州／頭 6」。h ≥ 43 會讀出表外資料，只有ベルグタイ（`8EF0`，h = 43）如此，視為無法顯示。
- 版面編號 = `T1[h]`，T1 在 `0x5342C`（`$942C`）。
- 部位表 T2 在 `0x53456`（`$9456`），每個版面 9 bytes：眼、鼻、口各一組（欄、列、寬），都是 1 列高。
- 分界 B：版面 6、9、14、15 為 20；版面 19 為 10；其餘為 15。
- 畫法：先放基本記錄的 30 格；每個為 1 的 bit，把對應區域的格子換成替換記錄同位置的格子。「上半」= 格號 < B 且不屬於眼鼻口的格；「下半」= 格號 ≥ B 且不屬於眼鼻口的格（格號 = 列 × 5 + 欄）。

驗證：`verify_kaodata_export.py` 在模擬器裡對 43 個頭 × 32 種 bit 組合、以及 80 張專屬頭像跑 `$A684`，攔下畫圖服務的 tile 與 ExRAM，和 `rom.py` 的結果比對，1456/1456 一致。

## 4. 攻略資料

### 4.1 兵科（bank 4，`$8000`）

- 能力表 `0x9B2C`：16 筆 × 8 bytes。
- 名稱指標表 `0x9BBC`：16 個 LE16。bank 21 `0x2B864` 有一份幾乎相同的副本，只有 byte 7 不同。

| byte | 內容 |
|------|------|
| 0 | 分類：0 步兵、1 特殊、2 騎兵 |
| 1 | 戦意 |
| 2 | 機動 |
| 3 | 近接（0 = E … 4 = A） |
| 4 | 突撃 |
| 5 | 矢弾（5 = 無遠程攻擊） |
| 6 | 防御 |
| 7 | 特殊：火砲兵 1、象兵 2、投石機 3，其餘 `FF` |

順序：軽歩兵、重歩兵、長槍兵、火砲兵、短弓兵、長弓兵、弩弓兵、象兵、投石機、狩猟騎兵、槍騎兵、蒙古騎兵、軽弓騎兵、突撃騎兵、騎士、武士。

bank 29（`$8000`）還有兩張表：

- `0x3B680`：徵兵價格 ÷ 100，16 bytes（300 … 1500）。
- `0x3B690`：電腦編軍團時的兵科優先順序（蒙古騎兵、武士、軽弓騎兵…）。

戦意、機動、等級、價格、優先順序都和 hishihishi 的兵科表一致。傭兵價格 = 徵兵 × 1.5 是外部資料的說法，ROM 裡沒找到。

### 4.2 交易品與商人（bank 20，`$A000`）

- 交易品名稱指標 `0x2912E`：12 個 LE16，依序是 けがわ、きぬ、ほうせき、ききんぞく、いやくひん、もっこうひん、とうじき、ガラス、おりもの、こうりょう、しょくりょう、ぶぐ。
- 商人名稱指標 `0x291A9`：4 個 LE16，依序是 ウイグル、チュウゴク、イスラム、ベネチア。
- bank 29 `0x3B650`：4 × 12 bytes。推定為「商人 × 交易品」的基本價格：每一列的食糧都是 10，武具是 55／40／45／50。還沒找到讀這張表的程式，意義未確認。

## 5. 大地圖（bank 45）

全畫面 32 × 30 tile，先放 960 個 tile 編號，再放 960 個 ExRAM byte。

| 地圖 | 偏移 |
|------|------|
| モンゴル編（14 地域，畫面上標 1–14） | `0x5A004` |
| 世界（33 國，畫面上標 1–33） | `0x5A784` |

配色用 §3 的主畫面調色盤。畫出來顏色合理，但沒有追到載入它的程式（推定）。

## 6. 戰場地圖（bank 32–37）

共 47 張：0–13 是モンゴル編的 14 地域，14–46 是世界 33 國。bank 9 `$A489`/`$A6B0` 算地圖編號：`$78C7` 是國編號，`$7468` 不為 0（世界編）時加 14。

每張 `0x364` bytes：

- 0–36 號在 `0x40000 + n × 0x364`（bank 32–35 連續存放）。
- 37–46 號在 `0x48000 + (n − 37) × 0x364`（從 bank 36 開頭重新起算）。
- bank 9 `$A412`／`$A532`／`$A5A9` 用常數 `$0364`、選擇子 `$E0` 或 `$E4` 算出位址。

| 記錄內偏移 | 長度 | 內容 | 載入程式 |
|------|------|------|------|
| `0x000` | 588 | 畫面 tilemap，28 × 21，列優先，每格一個值 v | `$A5A9` → WRAM 第 3 頁 `$7130` |
| `0x24C` | 140 | 出入國格：14 × 10，值 = 相鄰國編號（0 起算），`30` = 不是出入口 | `$A532` → `$7A12` |
| `0x2D8` | 140 | 地形：14 × 10，列優先 | `$A412` → `$7A9E` |

**畫面**：`$A62B` 先把 bank 9 `$ABC8`／`$AF88` 的外框範本複製到 WRAM `$6000`（tile）／`$63C0`（ExRAM），再把 tilemap 放在畫面 tile (2, 2)。值 v 換成 tile 與 ExRAM 的方式，是查 bank 9 `0x12702`（`$A702`）的表：`tile = 表[2v]`、`ExRAM = 表[2v+1]`。tile 都在 CHR bank 17。

**格子與 tile 的對應**：格 (x, y) 佔 2 × 2 tile。左上角在 tile 欄 `2x`；x 為奇數時在 tile 列 `2y`，偶數時在 `2y + 1`（偶數欄低半格）。依據：前 37 張圖的 65 個「城」格子全部落在 tile `01 02 / 03 04`，換成另一種奇偶時則全都對不上。

**地形**：

| 值 | 地形 |
|------|------|
| 0 | 平地 |
| 1 | 城 |
| 2 | 街 |
| 3 | 砂漠 |
| 4 | 森林 |
| 5 | 山岳 |
| 6 | 河川 |
| 7 | 湖・海 |

這個對照是拿第 1 國（オノン河流域）和 hishihishi 的 SFC 版戰場圖比對得出的：城 B = 1、街 A／C = 2，森林、河川、山岳的位置也對得上。出入國格的數字和該圖邊緣標的相鄰國號一致（1 起算）。

**調色盤（推定）**：
- 外框 tile 用子調色盤 0；地圖裡森林用 1、河川用 2、平地用 3，砂漠用 0。
- ROM 裡子調色盤 1–3 依序是綠／藍／棕的組合只有一份，在 bank 52 `0x69324`：`0F081837 0F0A2A37 0F0C2C37 0F071637`。匯出時用這份，但還沒追到戰場載入調色盤的程式。

**驗證**：`verify_battle_maps.py` 在模擬器裡對 47 張圖跑 `$A5A9`＋`$A62B`、`$A412`、`$A532`，比對畫面緩衝（tile＋ExRAM）、地形、出入國格，47/47 一致。

- bank 42、44 開頭是 tile 編號，但不是 32 寬的全畫面圖，用途未知。
- bank 43 開頭是（tile、ExRAM）對照與 2 × 2 組塊，推定是城／街內部地圖用的。
- bank 37 在第 46 號戰場（到 `0x4A1E8`）之後還有一大段資料，值多在 0–`0x4E`，推定是城／街內部地圖（hishihishi 記載 SFC 版有 H／n／W 型）。這段還沒解。
- 選擇子 `$EA`／`$EC`／`$ED` 的圖分別在 bank 17 `0x2208D`、bank 48 `0x60AE0`、bank 52 `0x68218` 附近畫出。
