# 天地を喰らうII 諸葛孔明伝（FC）ROM 格式

Capcom，1991，mapper 4（MMC3），PRG 512 KB（64 個 8 KB bank），CHR-RAM 8 KB，有電池 PRG-RAM。以下位址都是 CPU 位址；「bank b」指遊戲用 `$C6E5`（A = b）把 bank b 放在 $8000、b+1 放在 $A000 的 16 KB 視窗，所以 PRG 位移 = `b * $2000 + (addr - $8000)`。$C000–$FFFF 固定是 bank 62/63（PRG mode 0）。

## 1. 文字

- 印字程式 bank 62 `$D499`，控制碼分派 `$D4E3`。
- `00`–`09` 數字，`0A` 空白，`10`–`6C` 假名等（表見 `rom.py` 的 `FONT`）。
- `80`–`B6`：`code & 7F` 加濁點；`B7`–`C7`：`(code & 7F) - 9` 加半濁點。點畫在上一列（tile 72／73）。
- 人名用平假名的 へ／べ／ぺ 字形（和片假名同形），匯出時轉成片假名。
- `C8`–`F7` 是控制碼：bit `$20` 為 0 時先印一個空白，再當成 `code | $20` 處理。
  - `EA`／`EB`／`EC`／`ED` + 1 byte：bank $1C 的詞典字。表在 `$AA00`／`$A800`／`$A600`／`$A400`（lo），hi 在 +$100，字以 FF 結尾。
  - `F1 xx` 道具名，`F2 xx` 武將名。
  - `F3` 道具 `$4D`；`F4`／`F5`／`F6` 是 `$6621[$4B]`／`[$4A]`／`[$4C]` 的武將名；`F7` 是 `$6621[$05F0[$72]]`。
  - `EE`／`EF`／`F0` 在印字中不做事。在頁首時，`EE xx`／`EF xx` 是說話者 xx 的頭像（`$ADD8`）。頁首的 `E9` 畫 `$6078` 的頭像，`E8` 畫 `$6621[7]` 的頭像。
- `F8 lo hi` 呼叫程式，`F9 lo hi` 劇本標頭。
- `FA` 換行並縮排，`FB` 換行，`FC` 等按鍵（捲動），`FD` 換頁，`FE`／`FF` 結束。
- 訊息 m（0–2047）：視窗 bank `$2A + (m >> 9) * 2`，i = `m & $1FF`，指標 lo 在 `$8000 + i`，hi 在 `$8200 + i`。尾端有填充用的重複項。

## 2. 武將（bank $36）

指標表 lo `$9E00`／hi `$9F00`，共 256 筆。記錄格式：

| 位移 | 內容 |
|------|------|
| +00 | 高 4 位：遇敵章節（和 `$6011` 比較，見 §6）；低 4 位：0／5／10（**未解**） |
| +01 | **未解**（多為 32–80） |
| +02 | ちりょく |
| +03 | ぶりょく |
| +04 | すばやさ |
| +05..+0A | **未解**（+06 多為 $80 以上） |
| +0B | bit 7-5 ちけい（0 無、1 へいち、2 やま、3 もり、4 すいぐん；字串在 bank 60 `$8800`，每個 4 字）；bit 3-0 策略群 1–10（0 = 不會策略） |
| +0C | bit 2-0 ぶき（1 けん、2 おの、3 やり、4 ゆみ、5 かたな；字串在 bank 60 `$87EE`，每個 3 字，索引 ×3 經 `$FF41`）。整個 byte 複製到 `$6699` |
| +0D | **未解** |
| +0E..+13 | 頭像 6 列的 row index |
| +14／+15 | 頭像 6 列各自的 2 位元 bank：mask C0/30/0C/03/C0/30，shift 6/4/2/0/6/4，bank = v × 2；該列在 PRG `bank * $2000 + idx * $60`（6 個 2bpp tile） |
| +15 bit 2..0 | 漢字 0..2 屬於第 2 組字（bit `2 - j` 對應第 j 字） |
| +16..+18 | 漢字索引（FF = 結束） |
| +19.. | 假名名，FE／FF 結尾 |

- 入隊程式 `$E8F2` 把 +02／+03／+04 複製到 `$6681`／`$6675`／`$668D`（以戰鬥欄位為索引）。道具 $CE 讓 `$6681` +20；$D1／$D2 讓 `$668D` +10／+20。
- FB–FF 是雜兵：黃巾賊、兵士、盗賊、山賊、海賊。231 是無用的資料（名字含 め，漢字索引超出範圍；遊戲照樣讀進 $C000 以後，畫出亂碼）。
- **頭像**：ぶしょう畫面上以左右鏡像顯示（`$7A` = 0：tile 內 bit 反轉、tile 順序反轉），用調色盤 3 = [0F, 20, 37, 26]，畫在畫面 (16, 32)，48×48。
- **橫條拼貼**：和 I 一樣，每人紀錄直接寫 6 個 48×8 橫條（bank＋row index），沒有算式。不同的是沒有配色欄（調色盤固定），橫條分布在 3 個 window bank（0／2／4）。255 個 id（不算 231）只有 212 種組合，其中 2 種是全空白；其餘 210 種裡 6 條全是自己的 43 種，167 種至少和別人共用一條，共 368 條、每個位置約 62 種，除了空白條以外每條只用在固定位置。共用最多的條各被 13–14 張臉用到。全臉相同的不同人有 9 組（例：周倉／甘寧／張昭、金旋／曹仁、夏侯覇／劉琦、刑道栄／呂虔）；id 0、109、249–255（雜兵、オクガタ）是 6 條全空白的臉
- **專屬臉與分組**（`tenchi/strips_page.py` 的 `analyse`，純看資料）：專屬臉 43 張；其餘 167 張臉照 I 的方法連起來，同樣正好分成 2 組、互不相連：
  - **兜組** 94 張：基底臉 `2:48`、`2:4E`…`2:7E`（10 張，每張 6 個連號），每個位置 10 種
  - **官帽組** 73 張：基底臉 `2:84`…`2:A2`（6 張）與 `4:00`、`4:06`（2 張），每個位置 8 種
  - 和 I 一樣，第 1、2 條幾乎總是取自同一張基底臉（兜組 94 張中 81 張），第 5、6 條也偏向同一張
- **漢字**：bank $0E。第 1 組在 `$9800`（256 字），第 2 組在 `$B800`（64 字）。每字 32 byte，1bpp 16×16，tile 順序 TL、BL、TR、BR。名字畫在 (16 + 16j, 96)。字表 `data/kanji1.txt`、`data/kanji2.txt` 照 ROM 字形抄寫。234 呂蒙的資料指到「甘」，畫面上也顯示「呂甘」。
- **へいしすう**、SP 的計算方式：**未解**。

## 3. 道具（bank $34）

- 指標 lo `$8100`／hi `$8180`，128 筆，每筆是 [價格 LE16, 名稱 FF]。0–7 是金錢用的空項。
- `$B320[id]`：攻擊力（武器）或防禦力（防具）。
- `$B420[id]`：低 4 位 1–5 = 武器種類；`$80` 鎧、`$81` 兜、`$82` 盾、`$88` 其他裝備（馬、靴、書）、0 = 消耗品或重要道具。
- 隊伍持有：`$60CC + $FF60[slot]`，每人 6 格，bit 7 = 已裝備。攻擊力算到 `$66B1 + slot`。
- `$B4A0`：經驗值表，3 byte LE × 100（第 2–101 級），隊伍等級在 `$602B`。

## 4. 商店（bank $34，選單在 bank 56 `$9810`）

- 用地圖堆疊上「目前所在城鎮的地圖編號」Y = `$6013[$6012]` 查表。商店畫面所在的螢幕欄 `$63` = 12 時是武器屋，用 `$A7C0[Y]`，否則是道具屋，用 `$A880[Y]`。
- 清單 k（0–38）：指標 lo `$A940`／hi `$A968`，內容是道具 id，FF 結尾。
- 清單 0 只出現在洛陽（地圖 2）的武器屋。其他城鎮的 0 代表沒有該店。
- 城鎮名稱沒有對照表（訊息裡才有地名），所以只能用地圖編號標示。

## 5. 策略（名稱 bank $34，資料 bank $28）

- 名稱：lo `$8640`／hi `$8678`，id 1–54。id < $15 或 ≥ $1F 時名字後面加「のけい」。0 和 1 相同；53 和 54 相同。
- `$AD12[id]`：習得等級。隊伍等級 `$602B` 剛好等於這個值時，軍師就學會；FF = 不靠升級學會。
- `$AD49[id]`：類別。0 火計、1 水計、2 落石、3 回復、4 陣形、14 其他。
- 策略群 g（1–10，武將 +0B 低 4 位）：指標 lo `$AAF5 + g`／hi `$AAFF + g`，內容是 52 byte 的可用 id 清單（0 = 不可用）。習得程式在 `$A91F`。
- `$AA30`：敵方策略組，每組 6 byte。
- **消耗 SP 與效果數值：未解**（開局沒有軍師，選單進不去，所以也沒有從畫面對照）。

## 6. 遇敵（bank $28 `$B300`）

- 敵人數量：`$B3DF[亂數 & 15]` = [5,4,3,2,5,4,3,2,5,4,3,5,4,3,5,4]。
- 雜兵 id 由章節 `$6011`、地圖、位置決定（FB–FF，見 §2）。在大地圖 `$61` ≥ $55 且 `$63` < 8，或地圖 $36 時，會把 FC 換成 FD。條件分支沒有全部追完。
- 流浪武將：從 1–$E0 中找出 `$6200` 有 bit $10、且記錄 +00 高 4 位等於 `$6011` 的武將，隨機抽 1 人放進隊伍。
- 敵隊清單寫到 `$0300`（FB 以上是雜兵），再由 `$E04E` 搬進戰鬥欄位 `$6628`。
- `$8060[地圖] & $1F` 決定戰鬥背景 `$95`。
- **劇情戰的敵隊表、雜兵能力值（畫面上 200–250 兵）：未解。**

## 7. 地圖

- 螢幕格：bank $32 `$9000`，160 列 × 32 欄，每格是 [螢幕 id, 資料 bank]。資料 bank 是 $36 且 `$6320[id]` 已設時，改讀 bank $38（劇情進展後地形會變）。
- 螢幕：資料 bank `$8000 + id * 72`。前 64 byte 是 8×8 block，後 8 byte 是各 block 的第 9 位元（`byte[$40 + row]` 的 bit `7 - col`）。
- **一個螢幕在地圖上只佔 16×15 格**（256×240 pixel）：8×8 block 展開是 16×16 格，但第 16 列（y = 15）從不顯示，下一個螢幕緊接在第 14 列之後。門／傳送的座標也沒有 y = 15。舊版把螢幕當 256×256 疊，每個螢幕底下多出一列，大地圖因此出現條紋與接縫。
- tileset t（`$1D`）= 地圖的區域 `$48`。`$48` = 0（大地圖）時，第 80 列以上用 t = 0，以下用 t = 7。
- 每個 tileset 的資料：
  - bank `$DA60[t]`
  - block 頁 `$DA50[t]`，每個 block 4 格，順序 TL TR BL BR
  - 格的 tile 頁 `$FAEE[t]`..+3（TL、TR、BL、BR）
  - 格的調色盤頁 `$DA96[t]`：bit 0-1 是子調色盤，bit 2-7 是地形類型（`$D73D` 讀出）
- 地形類型：≥ 10 走不過（10 水、12 山…），8 = 門，9 = 傳送；`$F5E1` 依 `$86`（8 → 門 `$BD45`、9 → 傳送 `$BE5D`）分派。乘船狀態（`$84` bit 7，`$E7C1` 設定，只在地圖 $27／$69）改成 9–11 可走
- 地圖編號 m（`$47`）：
  - `$48` = bank $34 `$B700[m >> 1]` 的半個 byte（m 為偶數取高 4 位）
  - `$49` = `$B760[m] & $1F`：BG tile 組。tile $80–$FF 來自 bank `$10 + ($49 >> 3) * 2` 的 `$8000 + ($49 & 7) * $800`
  - 調色盤記錄：lo `$B820 + m`／hi `$B900 + m` → [起始索引, 顏色…, ≥ $80 結束]
- 位置 RAM：`$60` y 格、`$61` y 螢幕、`$62` x 格、`$63` x 螢幕。
- 大地圖 = 地圖 0，在格子第 68–90 列。大地圖調色盤有顏色循環（11／21 互換）。
- **大地圖的範圍**：沒有表，`export.world_view` 從所有在大地圖上的門／傳送端點出發，沿地形 < 10 的格子 flood-fill，再加上每格周圍的鏡頭範圍（鏡頭左上角＝隊伍格的 pixel 減 (128, 112)，即上 7 格、下 7 格、左 8 格、右 7 格）。走得到的格子都在第 69–90 列、第 2–26 欄，不會碰到格子邊緣；加上鏡頭後是第 68–90 列、第 2–27 欄的 374 個螢幕。其餘大地圖螢幕是填充：bank $24 的 2F（一塊有村子的陸地，在邊緣重複）、30（全山）、31（全水）與 bank $26 的 00（水＋海岸）、01（山）、02（水）。遊戲照樣畫得出來，但隊伍到不了、鏡頭也照不到。灰色大區是山（地形 12），分開的陸塊之間靠船（訊息裡的ふね）
- **門**（bank $36 `$8800`，判定在 bank 61 `$BD69`）：
  - 記錄 9 byte：[旗標 \| y, y 螢幕, x, x 螢幕, y', y' 螢幕, x', x' 螢幕, 地圖]
  - 旗標 bit $20 表示後面多 2 byte 劇本指標
  - x 和 x+1 兩格都算入口
  - 進門時把目前地圖推上 `$6013` 堆疊，位置存到 `$6018`；離開時彈出
- **傳送**（bank $36 `$98C0`，判定在 `$BE5D`）：
  - 9 byte：[y, y 螢幕, x, x 螢幕, 旗標 \| y', y' 螢幕, x', x' 螢幕, 地圖]
  - 直接換地圖，不用堆疊。從大地圖出發時位置存到 `$67ED`
- **各地圖在格子裡的範圍沒有表**。`export.py` 從門／傳送的目的螢幕出發做多源 BFS，只走同一資料 bank、不是單一 block 的螢幕，藉此推定範圍。共用同一區塊的相鄰地圖，邊界可能分錯。
