# FC 三國志 中原の覇者 ROM 格式

Namco（1988）。iNES：PRG 128 KB（16 × 8 KB）、CHR-ROM 128 KB（128 × 1 KB）、mapper 19（Namco 163）、battery。
ROM SHA-1（.nes 全檔）：`1962227fc6f5747c4937dca42ae3b07f081d3a2c`。

與 KOEI 作品無關：沒有 p-code VM，整個遊戲是 6502 原生碼。以下偏移一律是 **PRG 偏移**（檔案偏移 − 0x10）。
所有結論都用 `tools/nes_emu.py`（py65 + Namco 163 模擬）跑遊戲本身的程式驗證過，標「推定」者除外。

## Mapper 19（Namco 163）

| 位址 | 用途 |
|------|------|
| `$8000-$B800`（每 `$800`） | CHR 1 KB bank 0-7（PPU `$0000-$1FFF`） |
| `$C000-$D800` | 名稱表 bank；值 ≥ `$E0` 用 CIRAM |
| `$E000` / `$E800` / `$F000` | PRG 8 KB bank → `$8000` / `$A000` / `$C000`（低 6 bit，遊戲寫 0x31、0x3C 等，取 mod 16） |
| `$E000-$FFFF` | 固定為最後一個 bank（15） |
| `$5000` / `$5800` | 15-bit IRQ 計數器（bit 7 = 啟用），數到 `$7FFF` 觸發 |
| `$4800` / `$F800` | 128 bytes 內部 RAM 資料／位址（bit 7 自動遞增） |

遊戲每格畫面用 IRQ 在第 ≈159 掃描線切換 CHR bank（下半部訊息窗用別的字形／圖），所以截圖要依每條掃描線當時的
CHR bank 畫（`Nes.line_chr_banks()`、`Nes.screen()`）。設定 PRG bank 的副程式：`$E613`（slot 0）、`$E619`、`$E61F`。

## 文字編碼

文字就是 BG pattern table 1（PPU `$1000`）的 tile 編號：

| 值 | 字 |
|----|----|
| `0x01` | 空白 |
| `0x60-0x69`、`0xF0-0xF9` | 數字 0-9 |
| `0x80-0xAF` | あいうえお…わをん・？ |
| `0xC0-0xEF` | アイウエオ…ワヲンー！ |
| `0xFA-0xFD` | ャュョッ |
| `0xB5-0xB8` | ゃゅょっ（推定，未在畫面確認） |
| `0xFE` / `0xFF` | 濁點／半濁點，寫在被修飾字之後；畫面上放在上一列 |

武將姓名只有片假名（遊戲內不顯示漢字，唯 6 位君主有漢字 tile）。

## Bank 1（`$8000`）：資料表頭

Bank 1 開頭是 9 個 LE16 指標：

| 指標 | PRG | 內容 |
|------|-----|------|
| `$861C` | 0x261C | 州名 30 × 8 bytes |
| `$8012` | 0x2012 | 武將姓名指標 241 × LE16 |
| `$870C` | 0x270C | 開局資料 0xC30 bytes，開局時複製到 WRAM `$6000` |
| `$8B44` | 0x2B44 | （＝開局資料內的武將表，WRAM `$6438`） |
| `$92CC` | 0x32CC | 徳 241 bytes |
| `$93BD` | 0x33BD | 未解析，270 bytes |
| `$94CB` | 0x34CB | 30 × 16 bytes，每 byte = `y << 4 \| x`，戰場守方初始格（見〈戰場〉） |
| `$96AB` | 0x36AB | 同上，推定攻方 |
| `$988B` | 0x388B | 大地圖第 4-19 列 tile（32 × 16，地圖局部重畫用 `$A704`） |

### 武將姓名

指標指向片假名字串，最後一個字 bit 7 清為 0 當結尾（例：`0x42` = ウ 結尾、`0x7E` = 結尾的濁點）。
0-5 是 6 位君主（袁紹、馬騰、曹操、孫権、劉備、劉璋，與君主編號一致），6 起依五十音排序。
複製姓名到畫面緩衝區的程式：`$F1C7`（姓名 `$05DE`、濁點列 `$05D6`）。

### 州名

8 bytes：前 6 bytes 是下列的字（`0x01` 空白），byte 6、7 是上一列的濁點。顯示程式（bank 3 `$A27A`）：
名稱不滿 6 字時右移一格，byte 6 在第 0 字上方、byte 7 在第 2 字上方；6 字名時在第 1、3 字上方。
例：`cb fc cb fb c2 01 fe 01` = ジョシュウ（徐州）、`c8 ed c6 fc c2 01 01 fe` = ケンギョウ（建業）。

## WRAM（開局資料，劇本只有 200 年 1 月一個）

### 州 `$6000 + 36 × i`

| 偏移 | 內容 |
|------|------|
| 0 | bit 0-2 = 君主編號；bit 6、7 = 旗標（未解析） |
| 1-2 | キン（金） |
| 3 | 0 |
| 4-5 | トチ（土地） |
| 6-7 | サンギョウ（產業） |
| 8-11 | ジンコウ（人口，32-bit） |
| 12-13 | 0 |
| 14-15 | トウチド（統治度） |
| 16-27 | 武將編號 12 格，`FF` = 空 |
| 28-35 | `00 00 00 00 FF FF 00 00`（未解析） |

驗證：新野（#13）畫面 キン 200、トチ 25、サンギョウ 20、ジンコウ 19000、ブショウ 2、トウチド 55，與記錄一致。

### 武將 `$6438 + 8 × id`（存取副程式 `$F829`）

| 偏移 | 內容 |
|------|------|
| 0 | 旗標（`0x00` 或 `0x40`；君主與部分武將 0x00，未解析） |
| 1 | 体 |
| 2 | 知 |
| 3 | 武 |
| 4 | 高 4 bit = 第 3 種兵 ×100；低 4 bit 全為 0 |
| 5 | 忠（`FF` 顯示 `--`，君主） |
| 6 | 高 4 bit = 軍種（0 平、1 木、2 山；字形表 `$B6CB` 每項 4 tile，下半 +4）；低 4 bit 未解析 |
| 7 | 高 4 bit = 第 1 種兵 ×100；低 4 bit = 第 2 種兵 ×100 |

徳 另存在 PRG 0x32CC（以武將編號索引）。驗證：劉備 体78 知63 武53 徳99 忠-- 木軍 兵 400/400/200；
趙雲 体98 知55 武96 徳87 忠95 山軍。

## 頭像（sprite）

狀態畫面的頭像是 14 個 8×8 sprite 拼成的 24×32 臉（固定 bank 的 `$F47A`）：

- `$F53B`（PRG 0x1F53B）241 bytes：武將的 1 KB CHR bank（下半畫面 IRQ 時寫到 CHR slot 2，也就是 sprite tile `$80-$BF`）。
- `$F62C`（PRG 0x1F62C）241 bytes：bank 內的 16-tile 區塊 0-3，加到所有 tile 編號上（`<< 4`）。
- `$F71D` 模板 14 個 sprite `[dy, tile, attr, dx]`：11 個頭部（右半是左半水平翻轉）、2 個眼睛、1 個嘴。
  NES sprite 編號小者優先，所以頭部蓋在眼／嘴之上，眼／嘴只從頭部透明處露出。
- `$F513` 表情：4 種（`$06A4`，由劇情事件設定）× 2 張嘴（說話動畫），各指向 3 個 tile（左眼、右眼、嘴）。
- 調色盤：sprite 子調色盤 2 = `0F 20 27 17`，所有武將相同。

241 位武將共用 120 張臉（多位武將同一張），不是組合臉，沒有大眾臉零件。

## 戰略地圖（`$AD00`、固定 bank）

- 畫面存在 **CHR-ROM**：1 KB bank 112-119（CHR 0x1C000-0x1FFFF）當 pattern table 映射後，用 `$2007` 讀。
  開頭是 LE16 目錄（高 5 bit 有效），每個畫面是 RLE：`FF 值 次數`（次數 0 = 256），其餘照抄。
  `$AD00`（bank 7 於 `$A000`）參數 `$0A` = 目錄偏移、`$0C` = 1 時寫 2 KB（名稱表 0、1）。
- 畫面 0：名稱表 0 = 地形大地圖（第 0-19 列；20-29 列是訊息窗），名稱表 1 = 「ミチをみる」道路圖。
  地形圖 BG 用 CHR bank 4、5、14、7，道路圖 22、23、14、7（IRQ 分割線以上）。
- 調色盤：bank 2 PRG 0x4C6E 32 bytes（地圖 BG＋sprite）；道路圖 BG 子調色盤 0-1 換成 bank 12 PRG 0x19A30
  （0x19A00 起是淡入淡出各級）。
- 城：`$DE65`／`$DE83`（PRG 0x1DE65／0x1DE83）各 30 bytes 是 sprite x／y，游標判定為 16×16（`$DDC4`）。
  城的 sprite tile／屬性依君主：`$DE59` `2C 2D 03 01 2B 02`、`$DE5F` `01 01 00 00 01 00`。
- `$DEA1` 30 bytes `00/40/80` 與州記錄 byte 0 的 bit 6-7 完全一致（地域旗標，意義未解析）。

## 道路（相鄰）

bank 12 `$9A40`（PRG 0x19A40）30 × LE16 指標 → `[州, 道路編號]` 對，`FF` 結束；出陣時 `$BE29` 用它判斷
目標是否相鄰。道路編號 0x00-0x3F 共 64 條，大多雙向同號；カンチュウ⇄セイト（35/3A）與
フリョウ⇄ショウヨウ（36/2C）兩個方向號碼不同。

## 戰場

攻打某州時，戰場就是**被攻州**的地圖（`$E3E4`：`X = $0619` 目標州，呼叫 bank 7 `$ADCB`）：

- bank 2 `$8020`：LE16 metatile 表（`$9D91`，每種地形 4 個 tile：左上 右上 左下 右下）、LE16 地圖基底 `$6010`。
- 第 i 州記錄在 CHR-ROM `0x18000 + ((0x6010 + 0xE0 × i) & 0x7FFF)`：64 bytes 屬性表（原樣寫到 `$23C0`），
  接著 16 × 10 格地形（一格 16×16 px，第 0 列固定為 7＝上緣空列）。地形同時抄到 WRAM `$6E1A`／`$6F1A`。
- 地形：0 城（每張圖一格）、1 川、2 山、4 森、5 平地、6 荒地、7 上緣空列。
- BG CHR bank 36、37、6、7；調色盤 bank 2 PRG 0x4CCE（`$B231` 複製；地圖只用子調色盤 0-1）。
- bank 1 `$94CB`／`$96AB`：每州 16 格 `y << 4 | x`。洛陽戰實測：`$94CB` 前 4 格＝守方 4 隊出現位置
  （第 1 格就是城格），所以推定 `$94CB` 為守方、`$96AB` 為攻方候選格。

## 驗證

- `verify_kaodata_export.py`：241 人逐一跑 `$F47A`（頭像）與 `$F1C7`（姓名緩衝區），與資料集逐 pixel／逐字比對。
- `verify_battle_maps.py`：30 張戰場跑 `$ADCB`、大地圖跑 `$AD00`，比對名稱表、屬性表與 WRAM。
- 遊玩中截圖比對：劉備、趙雲狀態畫面頭像；新野州資訊；洛陽戰場畫面（名稱表＋調色盤）。

## 外部資料

- [renote.net](https://renote.net/articles/2022)：武將名全為片假名、行動消耗「命令書」（畫面左下的「3枚」），與 ROM 一致。
- `data/kanji_names.tsv`（[EXT]）：漢字由讀音比對 `sangokushi/` 的 san1-fc 人物表，多名同音者依所在州／勢力選定，
  另 32 名人工判讀；其餘 61 名留空。
