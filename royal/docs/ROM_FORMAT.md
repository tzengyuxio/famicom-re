# FC ロイヤルブラッド ROM 格式

偏移量一律是 **PRG 偏移**（檔案偏移 − 0x10）；bank = 8 KB（bank n 在 PRG `n × 0x2000`）。標「推定」的是還沒用遊戲畫面或程式確認的推論。

## 1. 硬體

- iNES 標頭 `4E 45 53 1A 10 20 52 …`：PRG 256 KB（32 × 8 KB）、CHR **256 KB**（64 × 4 KB）、MMC5、電池。
- 向量：RESET `$F500`、NMI `$F60C`。`$C000` = bank 30、`$E000` = bank 31 固定；主程式期間 WRAM 第 0 頁在 `$6000`。
- 背景用 ExRAM 擴充屬性（`$5104 = 1`）：ExRAM bit 0–5 = 4 KB CHR bank（64 個全部用得到），bit 6–7 = 子調色盤。
- KOEI p-code：函式開頭 `JSR $DED9`（bank 30），p-code 堆疊指標 `$02-$03`，第 1 個引數在 SP+2。
- NMI 期間 `$F6C0`（bank 31）依佇列把 tile／ExRAM 從 ROM 或 RAM（指標 `$99-$9A`）寫進 PPU。
- 調色盤：戰略畫面（地圖、頭像）共用 bank 31 `$F070`（PRG 0x3F070）的 BG 調色盤；戰鬥 BG 在 PRG 0x13DD0（bank 9），精靈 0x13DE0。

| bank | 內容 |
|------|------|
| 0–2、4–12、14、16、30 | p-code／程式 |
| 13 | 戰鬥用部隊標籤（§4.3）等 |
| 18 | 4 劇本資料（§2） |
| 19 | 名稱表（人物、領地、部隊、家）、戰場地形（§3、§6） |
| 20 | 戰略地圖（§5）與其他畫面排列 |
| 21 | 頭像表（§4） |
| 23 | 戰鬥畫面框、戰場 metatile（§6） |
| 22、24–26 | 其他畫面排列（未逐一解） |
| 15 | 全 FF |

## 2. 劇本（bank 18，PRG 0x24000 + 0x800 × s）

| # | 名稱 | 開局後經過年數（`+0x06`） |
|---|------|------|
| 1 | エランとレッドワルト | 0 |
| 2 | フェリアス家のきき | 5 |
| 3 | ティリアンの戦い | 10 |
| 4 | ロイヤルブラッド | 15 |

選劇本後整塊 0x800 bytes 複製到 WRAM `$6000-$67FF`（模擬器確認：開局後只有執行期指標與 `+0x00`、`+0x76B` 改變）。表內指標都是 `$6000 + 偏移`；ROM 裡指標欄是 0，開局才串起來。劇本名取自選劇本畫面。

- `+0x00–0x34` 標頭：`+0x06` 年數差（年齢計算用），`+0x07–08` = `0C 01`（推定：月／年），`+0x0A–0x2B` 全 FF、`+0x2C` = 5（未知）。
- `+0x765` = ASCII `KOEI`，之後到 `+0x7FF` 為 0／FF（執行期工作區）。

### 2.1 家（`+0x35`，4 bytes × 30 槽）

槽號 = 家編號（§3.3 家名表的索引），空槽 `FF FF FF 00`。

| 偏移 | 內容 |
|------|------|
| 0 | 家編號 |
| 1 | 当主（人物編號） |
| 2 | 操作者（ROM 裡都是 FF＝電腦；開局時填入玩家） |
| 3 | 旗標位元（劇本 1 每家一個不同 bit：ランカシア 40、ブランシェ 02、ライル 01…；劇本 3、4 出現 06、21 這種組合，推定是同盟或標記色，未解） |

劇本 1 的 7 家：ランカシア（エセルレッド，14 領）、ブランシェ（エラン）、ライル（レッドワルト）、コーラル、クリサリス、フェリアス、モーブル。玩家可選的只有 4 家（劇本 1：ブランシェ、ライル、コーラル、クリサリス），選單字串在 bank 1 0x2620（4 劇本 × 4 家）。

### 2.2 人物（`+0xAD`，10 bytes × 64）

槽號 = 人物編號 = 姓名表索引 = 頭像編號。`+5 = FF` 表示該劇本沒有這個人。

| 偏移 | 內容 |
|------|------|
| 0–1 | 同領地下一個人物的指標（執行期） |
| 2 | 知力（推定名稱，畫面上是第 1 個圖示） |
| 3 | 武力（同上，第 2 個圖示） |
| 4 | 魅力（心形圖示） |
| 5 | 所在領地（0 起算） |
| 6 | 家 |
| 7 | 身分：1 当主、2 家臣、4 在野（推定；劇本 1 的 4 多半集中在 ランカシア 的領地 22） |
| 8 | 一族（推定）：FF 或家編號；例：ギメルシュ 劇本 1 是 4（クリサリス）的在野、劇本 2 成為 クリサリス 当主 |
| 9 | 只有当主非 0（劇本 1：エセルレッド 42、レッドワルト 9、エラン 9…，劇本間會變），意義未知 |

確認：劇本 1 選家畫面 エラン（4 號）顯示 82／87／76、「家臣 4」、19 才；指揮畫面 4:バーニシア 的領主是 カル（16 號，`+5 = 3`）。

### 2.3 領地（`+0x32D`，36 bytes × 30）

| 偏移 | 內容 |
|------|------|
| 0–1 | 第一個人物的指標（執行期） |
| 2–3 | 金 |
| 4–5 | 食料 |
| 6–7 | 兵（「雇用」會問要雇幾人；無主領地為 0；戰鬥時防守方 4 隊兵力合計＝此值） |
| 8 | 右欄第 1 項（山形圖示，推定 開発） |
| 9 | 右欄第 2 項（作物圖示） |
| 10 | 右欄第 3 項（心＋人圖示，推定 民忠） |
| 11–13 | 執行期旗標（行動過會變成 `01 00 01`、`FF FF 01`） |
| 14 | 支配家（FF = 無主） |
| 15 | 0 |
| 16–35 | 5 槽 × [部隊種類（§3.4 編號）, 兵力 LE16, 1 byte（多為 2）]，FF = 空 |

確認：劇本 1 第 4 領 バーニシア ROM 值 141／128／112／45／40／41，開局一個月後畫面 141／128／112／42／37／38（右欄三項每月下降）。

16–35 的 5 槽只出現 0–14 號（怪物與傭兵），兵力等於 §3.4 的初期兵力；示範模式的戰鬥中防守方的第 5 部隊不是這裡的部隊，推定是該領地可雇用的傭兵名單（未確認）。

## 3. 名稱表（bank 19）

文字是半形片假名（cp932 A6–DF），0 結尾；`rom.kana()` 以 NFKC 轉全形。

### 3.1 人物姓名（0x26004，14 bytes × 64）

| 偏移 | 內容 |
|------|------|
| 0–9 | 姓名 |
| 10 | 0 |
| 11 | 年齢基數：年齢 ＝ 這值 ＋ 劇本年數差 ＋ 1（エラン 18 → 劇本 1 畫面 19 才） |
| 12 | 0 |
| 13 | 未知（高、低 4 位元各 0–3） |

### 3.2 領地（0x26384，21 bytes × 30）

| 偏移 | 內容 |
|------|------|
| 0–10 | 領地名 |
| 11–18 | 相鄰領地（0 起算，FF 補滿；與地圖相符，例：1 キャメロン ↔ 2、3） |
| 19–20 | 戰略地圖上家標記的格（x, y，§5 的 14×19 格內；模擬器確認 27 個標記格全部對上） |

### 3.3 家名（0x26798，11 bytes × 41）

0 ランカシア、1 ブランシェ、2 ライル、3 コーラル、4 クリサリス、5 フェリアス、6 モーブル、7 スレテート、8 トルディン、9 テュードリア、10 ディアス，11 起是其他姓氏（ホーリー、ハロルド…）。劇本裡只出現 0–10。

### 3.4 第 5 部隊（0x265FA，18 bytes × 23）

0–9 名稱，10–17 數值：

| 偏移 | 內容 |
|------|------|
| 10 | 0 |
| 11 | 推定攻擊力（魔術、パスハ、ドラゴン 為 0） |
| 12 | 推定防禦力 |
| 13 | 初期兵力（示範模式：ドラゴン 160、マシェーティ 130 與戰鬥畫面一致） |
| 14 | 0 |
| 15、16 | 未知 |
| 17 | 類別位元：09／11 怪物、12 傭兵、0A 魔術、0C パスハ・ドラゴン |

0–8 怪物（オーガ オーク オログハイ ガーゴイル サラマンダー スケルトン バグベア ファハン ワイバーン）、9–14 傭兵（ガンナー シューター ピルムス パイクス ランツクネヒツ ハイランダース）、15–20 魔術（ミーティア サンダラス ポイズン フレイム マシェーティ チル）、21 パスハ、22 ドラゴン。

### 3.5 戰鬥標籤（bank 13 `$A5CA`，PRG 0x1A5CA）

27 個 LE16 指標（`$A000` = bank 13）：4 個軍隊部隊 ジュウソウキヘイ（重装騎兵）、ジュウソウホヘイ（重装歩兵）、チョウキュウヘイ（長弓兵）、ジュウソウホヘイ，接著是 §3.4 的 23 種（前面有控制碼 `1B 4B`）。戰鬥畫面的「じゅうそうほへい VS ちょうきゅうへい」就是這些。

## 4. 頭像（bank 21）

每張 5×6 tile（40×48），30 個 tile id ＋ 30 個 ExRAM byte（CHR bank 16–26 ＋子調色盤），row-major，用戰略畫面 BG 調色盤（0x3F070）。沒有組合臉。

| 表 | tile id | ExRAM | 張數 | 用途 |
|----|---------|-------|------|------|
| 人物 | 0x2A004 | 0x2A784 | 64 | 頭像編號＝人物編號 |
| 相談役 | 0x2AF04 | 0x2AF7C | 4 | 開局選相談役的 4 人 |
| 部隊 | 0x2AFF4 | 0x2B2A6 | 23 | §3.4 同順序（怪物、傭兵、6 位魔術師、パスハ、ドラゴン） |

- 人物頭像函式 `$DB3B`（bank 30，p-code）：引數 (x, y, 人物紀錄指標)，編號 ＝ (指標 − `$60AD`) / 10，以 bank 21（`$F5`）、`$A004`／`$A784` 為來源排進 NMI 佇列。`$DB19` 引數 (x, y, 家) 畫家紋；`$DB6F` 一帶用 bank 20 `$A34C`。
- 驗證：選家畫面遊戲呼叫 `$DB3B` 時把指標換成 64 人，遊戲畫出的格子＋調色盤與資料集逐 pixel 一致；相談役畫面 4 張與表一致。部隊頭像只有靜態解碼（圖像正常，未在遊戲中追到呼叫）。
- 頭像沒有編號：人物的臉由紀錄指標推出（`$DB3B`：序號 = (指標 − `$60AD`) / 10），相談役與部隊是表內序號，所以 kaodata 的 portraits 不帶 `code`。相談役畫面（「ソウダンヤクハダレニシマスカ?」）只顯示 4 張臉，ROM 裡找不到相談役名字；部隊頭像與 §3.4 名稱表同順序，kaodata 用該名稱當 `name`。

## 5. 戰略地圖（bank 20）

14×19 格，tile id 0x286E8、ExRAM 0x287F2，遊戲畫在 name table (16, 4)。領地編號已在圖裡，各家的標記另外畫在 §3.2 的標記格上。調色盤 0x3F070。

## 6. 戰場地圖

- 地形：bank 19 0x26A66，80 bytes × 30（每領地一張，10×8 格 row-major）。高 4 位元＝地形，低 4 位元在 ROM 為 0；戰鬥開始時複製到 `$6860`，低 4 位元填部隊編號（1–5 防守、6–10 攻擊）。
- metatile：bank 23 0x2E6D6，16 × 4 tile id（左上、右上、左下、右下），後接 16 × 4 ExRAM byte。格 (c, r) 畫在 name table (6 + 2c, 7 + 2r)。
- 出現的地形值：0 平地、1（未見於畫面）、2 守方本陣（城內旗）、3 攻方本陣（紅旗，固定在第 0 欄）、4、5 丘、6、8–11（推定林／山等，未逐一確認名稱）、12 城門、13 城牆、14／15 城角。
- 驗證：示範模式第一場戰鬥（リンディニス）複製地形後，把 `$6860` 換成 30 張中的每一張讓遊戲畫，沒有部隊的 70 格全部與靜態解碼一致。

## 7. 未解

- 人物 `+7` 的 4（在野？）、`+8`（一族？）、`+9`（当主專屬值）、姓名表 `+13`。
- 屬性名稱「知力／武力／魅力」與領地右欄「開発／作物／民忠」是依圖示推定，遊戲畫面只有圖示。
- 家 `+3` 旗標位元在劇本 3、4 的組合意義。
- 領地 16–35 的 5 槽（推定傭兵候補）與末位元組；部隊表 +11、+12、+15、+16。
- 標頭 `+0x07–0x2C`。
- 魔術師（6 位）屬於哪一家、寶石（Gemfire 的 gem）存在哪裡尚未找到。
- 地形值 1、4、6、8–11 的正式名稱。

## 8. 外部資料對照
