# FC 信長の野望・武将風雲録 ROM 格式

KOEI，1991（FC 版 1991-12-21，ja.wikipedia），FC。ROM 直接讀 `roms/Nobunaga no Yabou - Bushou Fuuun Roku (Japan).zip` 內的 `.nes`。

本文的偏移一律是 **PRG 偏移**（檔案偏移減 `0x10`），除非另外寫明。CPU 位址寫成 `$xxxx`。「bank n」指 8 KB 的 PRG bank，PRG 偏移 = `n × 0x2000`；bank 內的表前 4 bytes 通常是 `4C 00 00 00`，資料從偏移 4 起。標「推定」的欄位還沒用遊戲程式或畫面確認。

## 1. 硬體與程式

| 項目 | 內容 |
|------|------|
| iNES 標頭 | PRG 512 KB（64 × 8 KB）、CHR 256 KB、mapper 5（MMC5）、有電池 |
| 向量 | NMI `$F60C`、RESET `$F500`、IRQ `$FE9C` |
| RESET 的 bank 設定（`$F565`） | `$5113–$5117 = 04 FF FF FE FF`，影子在 `$90–$94` |
| PRG-RAM | `$5113` 選 `$6000` 的頁；`$5114–$5116` 的 bit 7 清除時，`$8000–$DFFF` 映射的是 PRG-RAM 頁（戰場畫面的緩衝區就放在 RAM 頁 1 映射到 `$8000` 時的 `$8508`） |
| ExRAM | 擴充屬性模式：每個 BG tile 一個 ExRAM byte，bit 0–5 = 4 KB CHR bank，bit 6–7 = 子調色盤 |
| p-code | 函式開頭 `JSR $E31E`；opcode 分派表低位 `$EB33`、高位 `$EC33`；系統呼叫 `$ED33`（最後推入的值是服務編號）。`6x` = 推入常數 x，`8E lo hi` = 推入 16 位元常數 |
| 系統服務 | 3 = 映射 bank；9 = 畫圖（x、y、寬、高、tile 指標、ExRAM 指標、來源選擇子：`$C0 + bank`，`$FF` 表示 RAM） |
| 記憶體複製 | `$F199`（原生）：(選擇子, 來源, 目的, 長度) |
| 部分程式 | 有些模組是 C 編譯的原生 6502 碼（以 `$06` 當框架指標），例如戰場畫面組裝 bank 23 `$A42F` |

`tools/nes_emu.py`（由 L'Empereur 的模擬器改成 512 KB PRG，並補上 `$8000–$DFFF` 的 PRG-RAM 頁）可以開機、按鍵、存讀狀態、截圖。`tools/pcode_emu.py` 是只有 CPU＋MMC5 的最小環境，用來單獨呼叫遊戲的函式（頭像、戰場畫面）。

## 2. 劇本

| 劇本 | 名稱 | 資料 bank | 姓名 bank | 標頭（偏移 4–6） |
|------|------|------|------|------|
| 1 | 戦国の動乱（1555 年 3 月） | 35 | 33 | `01 4F 03` |
| 2 | 信長包囲網（1571 年 3 月） | 36 | 34 | `02 5F 03` |

標頭 = [劇本編號][年 − 1476][月]。劇本資料 bank 在遊戲中原封不動載到 WRAM 頁 2 的 `$6000`，所以裡面的指標都是 WRAM 位址（= `$6000` + bank 內偏移）。

| bank 內偏移 | 內容 |
|------|------|
| `0x007` | 國 48 × 32 bytes |
| `0x607` | 茶器 48 × 3 bytes |
| `0x698` | 大名 48 × 32 bytes（有效的：劇本 1 為 41 家、劇本 2 為 32 家） |
| `0xC98` | 武將 13 bytes × 256 格（劇本 1 用 250 格、劇本 2 用 255 格，其餘是空格串列） |

### 2.1 國（48 × 32 bytes）

| 偏移 | 欄位 |
|------|------|
| 0–1 | 第一位武將的指標（武將以 next 指標串成串列） |
| 2–3 | 第二個指標（多為 0；推定為浪人串列） |
| 4–5 | 金 |
| 6–7 | 米 |
| 8–9 | 石高 |
| 10 | 治水 |
| 11–12 | 町 |
| 13 | 推定：文化（畫面「眼睛」圖示） |
| 14–15 | 推定：技術（畫面「鎚子」圖示） |
| 16 | 兵忠 |
| 17–18 | 城 |
| 19–21 | 未知 |
| 22–23 | 大名記錄的指標（`$6698 + 0x20 × 大名編號`；0 = 無主） |
| 24–25 | 兵 |
| 26–27 | 鉄砲 |
| 28 | 訓練 |
| 29 | 民忠 |
| 30–31 | 未知 |

### 2.2 國名與相鄰（PRG `0x416B0`，48 × 13 bytes，劇本共用）

`[國名 4 bytes SJIS + 00][未知 1][相鄰國 × 最多 7，FF 結尾]`。相鄰國 byte 的低 6 bits 是國編號，高 2 bits 未知（推定為方向）。

國的順序：陸奥、陸前、出羽、越後、常陸、下野、下総、安房、上野、武蔵、能登、越中、相模、甲斐、駿河、信濃、遠江、飛騨、三河、加賀、伊勢、越前、美濃、尾張、近江、伊賀、丹後、山城、大和、紀伊、摂津、丹波、播磨、因幡、備前、出雲、安芸、石見、周防、讃岐、阿波、伊予、土佐、豊後、肥前、肥後、日向、薩摩。

### 2.3 大名（48 × 32 bytes）

| 偏移 | 欄位 |
|------|------|
| 0–1 | 大名本人的武將指標 |
| 2–4 | 未知（劇本 1 多為 `FF FF FF`；推定為同盟／婚姻對象的大名編號） |
| 5–6 | 未知 |
| 7–28 | 未知，像是每 2 bits 一筆的表（多為 `55`；推定為對其他大名的關係） |
| 29 | 未知（全為 50） |
| 31 | 大名編號 |

### 2.4 武將（13 bytes）

第 i 格的姓名指標固定是 `$A004 + 20 × i`（姓名 bank 映射在 `$A000`），所以姓名表第 i 筆就是第 i 格武將。已對照畫面：織田信長 政治 95、戦闘 87、教養 80、野望 100、年齢 21；柴田勝家 忠誠 63。

| 偏移 | 欄位 |
|------|------|
| 0–1 | 同國下一位武將的指標（0 = 結尾） |
| 2–3 | 姓名指標 |
| 4 | 政治 |
| 5 | 戦闘 |
| 6 | 教養 |
| 7 | 旗標（`0x80`／`0x40`／`0x00`，bit 3 推定為持有茶器；信長 = `0x88`） |
| 8 | 未知（`0x20`、`0x21`、`0x30`、`0x31`、`0x36`） |
| 9 | 0 |
| 10 | 所在國 |
| 11 | 所屬大名編號 |
| 12 | 忠誠（大名本人為 100，畫面顯示 --） |

## 3. 姓名表（bank 33／34，偏移 4 起，20 bytes）

| 偏移 | 欄位 |
|------|------|
| 0–6 | 姓（SJIS，0 補齊） |
| 7–13 | 名 |
| 14 | 魅力 |
| 15 | 野望 |
| 16 | 未知（推定為相性） |
| 17 | 生年 − 1476（信長 58 → 1534，與 1555 年 21 歲相符） |
| 18–19 | 頭像碼（LE16，見 §5） |

| 範圍 | 劇本 1（bank 33） | 劇本 2（bank 34） |
|------|------|------|
| 開局武將 | 0–249 | 0–254 |
| 空格 | 250–253 | — |
| 改名後的姓名 | 254 徳川家康、255 豊臣秀吉 | 255 豊臣秀吉 |
| 登場武將 | 256–376（121 人，多賀谷政広 … 徳川秀忠） | 256–347（92 人） |

ROM 裡沒有讀音（假名）。名字之後空 20 bytes，接著是 48 個茶器名（13 bytes：12 bytes SJIS + 0）。

### 3.1 外字

字型表（§7）在 SJIS `EB9F–EBA6` 放了 8 個外字，每個 16×16 的字裡塞 1.5 個漢字，用來把 3、4 字的姓擠進 2、3 格：

| 位元組 | 文字 |
|------|------|
| `EB9F EBA0 EBA1` | 長宗我部 |
| `EBA2 EBA0 EBA1` | 香宗我部 |
| `EBA3 EBA4` | 鳥屋尾 |
| `EBA5 EBA6` | 佐々木 |

### 3.2 登場武將（bank 37，偏移 4 起，8 bytes）

劇本 1 的串列 121 筆，以 `00 FF …` 結束；劇本 2 的 92 筆從 PRG `0x4A3D4` 起。第 k 筆對應姓名表第 256 + k 筆（所在國吻合：多賀谷 → 下総、北条氏邦 → 相模）。

`[登場年 − 1476][國（FF = 未定）][未知][政治][戦闘][教養][旗標][未知]`

## 4. 茶器（劇本 bank `0x607`，48 × 3 bytes）

`[值][持有者武將指標 LE16（0 = 無）]`。第一個 byte 大致遞增，`F8`／`FC` 只出現在無持有者的茶器（推定為價值或順位，未確認）。名字見 §3。

## 5. 頭像

頭像分派函式是 p-code `$A174`（`$8000` = bank 7、`$A000` = bank 58），參數 (x, y, 頭像碼)，最後用服務 9 從 RAM 畫 5×6 tile（40×48）。

### 5.1 專屬頭像（碼 < `0x8000`）

每筆 60 bytes：30 個 tile 編號 + 30 個 ExRAM byte。

| 頭像編號 f | 位置 |
|------|------|
| 0–71 | bank 56 第 f 筆（`0x70004 + 60f`） |
| 72–169 | bank 57 第 f − 72 筆（`0x72004 + 60(f − 72)`） |
| 170–211 | bank 56 第 f − 98 筆 |

人物資料用到 210 個；168、169 不屬於任何人物，由遊戲程式用常數頭像碼叫出。212 個編號都用模擬器確認過。

設頭像的 p-code 是 bank 0 的 `$A7A9`（遠呼叫：`8e <碼> 00`、push x、push y、`8e a9 a7 8e c0 00 62 e9 04 f3`），它把碼、座標存到 `$7D3C`／`$7D3E`／`$7D3F`，再由 bank 58 `$A4AE` 交給 `$A174`。以常數 168、169 呼叫的地方全 ROM 只有 4 處：

| 頭像 | 呼叫點（PRG） | 場面 |
|------|------|------|
| 168 | bank 17 `$AEE5`（0x22F0C、0x22F48） | 事件。第一段印訊息 0x3F「沢彦ガ／シンネンノアイサツニ／ヤッテマイリマシタ」，第二段印 0x4D「政秀寺開山　沢彦」；呼叫者是 `$7D6A` 事件分派表裡的 `$B05E`（`$79C7` bit 6 的一次性事件，字串「金2000ﾋﾂﾖｳﾃﾞｽｶﾞ建築ｼ」，推定是安土城建築，訊息 0x40／0x43）、`$B0E1`（bit 5，字串「ｶｲﾒｲｼ」，推定是稲葉山改名岐阜，訊息 0x3C／0x3D）與 `$AF34` |
| 169 | bank 6（0xC86F） | 存檔／結束畫面：「セーブシテ」「ユクエヲミマモリ」「スイッチハ、ワスレズニキリマショウ。アーメン」「マタオ会イスル時ヲ楽シミニ・・・・」 |
| 169 | bank 16 `$85F6`（0x20631） | 來訪者處理：`$7D94` 是來訪者種類，`if $7D94 == 9` 才設 169；`$9DD9` 的 14 筆名稱表第 9 筆是「ﾙｲｽ=ﾌﾛｲｽ」（0 山師、1 金山ｼｮｳﾆﾝ、2 鉄砲ｶｼﾞ、3 ﾔﾐｼｮｳﾆﾝ、4 越中富山ﾉｸｽﾘｳﾘ、5 千利休、6 津田宗及、7 長谷川宗仁、8 松井友閑、9 ﾙｲｽ=ﾌﾛｲｽ、10–13 狩野永徳・長谷川等伯・海北友松・狩野山楽） |

訊息編號 < 200 的表在 bank 20 `$AF04`（PRG 0x28F04，`$A000` 起算的指標）。所以 F168 是沢彦、F169 是ルイス=フロイス（畫面也對得上：光頭老僧、留鬍子的西洋人）。

### 5.2 組合臉（碼 bit 15 = 1）

| bits | 內容 |
|------|------|
| 0–2 | 頭（表裡有 0–4，用到的只有 0–3） |
| 3–4 | 上（頁 0–3） |
| 5–6 | 下 |
| 7–8 | 眼 |
| 9–10 | 鼻 |
| 11–12 | 口 |

5 個頭畫的樣子：0 甲冑、1 武士（髷）、2 烏帽子（用的是足利義氏、京極、三淵、土岐等）、3 僧形（下間、本願寺光寿、前田玄以等）、4 前髪（沒人用）。kaodata 的變體名稱就用這些（看圖與使用者歸納，遊戲裡沒有這些字）。

頭 h 的第 p 頁（p = 0–3）在 `0x745F6 + (4h + p) × 60`（bank 58 `$A5F6`），同樣是 30 tile + 30 ExRAM。每格取所屬區域選中那頁的 tile 和 ExRAM。

區域每個頭不同，表在 `0x745A6`（bank 58 `$A5A6`），每頭 8 個 LE16：`[分界格][未知][眼起點][眼格數][鼻起點][鼻格數][口起點][口格數]`。眼、鼻、口各是連續的格（5×6 列優先編號）；其餘的格，編號小於分界格的歸「上」，其餘歸「下」。5 個區域剛好切分 30 格。

| 頭 | 分界 | 眼 | 鼻 | 口 |
|------|------|------|------|------|
| 0 | 20 | 10–12 | 15–17 | 21–22 |
| 1 | 20 | 11–13 | 17–18 | 22–23 |
| 2 | 15 | 10–12 | 15–17 | 20–22 |
| 3 | 15 | 12–14 | 17–19 | 23–24 |
| 4 | 15 | 10–12 | 15–16 | 20–21 |

用到的組合碼 251 個（`0x8000–0x9FE9`）。驗證：模擬器跑 `$A174`，212 個專屬編號、251 個用到的碼、每頭 × 每區 × 每頁、再加 200 個固定亂數組合，共 728 個碼的 tile 與 ExRAM 全部一致。

調色盤：主畫面 BG 調色盤在 `0x7F401`（bank 63 `$F401`）= `0F 27 37 30  0F 27 2A 16  0F 11 16 27  0F 16 37 2A`。

## 6. 大地圖

bank 53，30×26 tile 畫在 (1, 2)：tile `0x6A1A8`（`$A1A8`）、ExRAM `0x6A4B4`（`$A4B4`），選擇子 `$F5`。呼叫處在 PRG `0x766` 的 p-code。調色盤同 §5。

## 7. 字型

bank 48 偏移 4 起是 SJIS → 字形的表，10 bytes 一筆：`[SJIS LE16][4 個 tile 編號 LE16]`（16×16 = 2×2 tile，CHR ROM 內偏移 = 編號 × 16），共 642 字，依 SJIS 排序。

## 8. 戰場

一場合戰先在「野戰」地圖打，籠城後改到「城」地圖。兩種地圖都是六角格：奇數行（column）往下錯半格。

| 遊戲變數（WRAM 頁 2） | 意義 |
|------|------|
| `$79CE` | 戰場所在國 |
| `$7D62` | 地形格（每格 1 byte，低 4 bits 是地形） |
| `$7DFC` | 城地圖的第二層（bank 51） |
| `$7D17` bit 1 | 1 = 城地圖 |
| `$7F4E`／`$7F50`／`$7F52` | 寬、高、格數 |

### 8.1 野戰地圖（bank 49，48 張 × 154 bytes，14×11）

載入：bank 23 `$A070` 把 bank 49 `$A004 + 154 × 國` 複製到 `$7D62`。

| 地形 | 意義 | 圖塊 |
|------|------|------|
| 7 | 平地 | 0 |
| 8 | 丘陵 | 1 |
| 9 | 林 | 2 |
| B | 海・湖（推定） | 3，上方是 B／D 或第一列時用 4 |
| C | 山 | 5 |
| D | 川 | 6，上方是 B／D 或第一列時用 7 |

紀伊、安芸、伊予、肥後 4 國載入後會把一格改成 `0x0A`／`0x4A`（推定是城的位置），畫面上仍畫成平地。

### 8.2 城地圖（bank 50＋51，49 張 × 143 bytes，13×11）

載入：bank 23 `$A1F5` 把 bank 50 `$A004 + 143 × n` 複製到 `$7D62`、bank 51 同位置複製到 `$7DFC`。n = 國；但 `$79CE = 24`（近江）且 `$79C7 = 0x40`、`$79CB = 0xFF` 時用第 48 張（安土）。

| 地形 | 圖塊 | 地形 | 圖塊 |
|------|------|------|------|
| 0 | 12 | 6 | 36 |
| 1 | 31 | 7 | 37 |
| 3 | 33 | 8 | 38 |
| 4 | 34 | 9 | 39 |
| 5 | 35 | C | 40 |
| D | 28，上方是 D／0 或第一列時用 29 | | |

bit 7（`0x84`、`0x85`、`0x86`）不影響畫面。第二層（bank 51，`0x00–0x3C`）不參與繪圖，意義未知（推定為城郭結構／防禦）。地形 1–6 的意義（城門、櫓、石垣……）未確認，見輸出的圖例。

### 8.3 畫面組裝（bank 23 `$A42F`，原生碼）

先把底圖（32×30 tile ＋ 32×30 ExRAM）複製到緩衝區，再逐格畫 2×2 tile 的圖塊，最後用服務 9 畫全畫面（選擇子 `$F4`）。

| | 野戰 | 城 |
|------|------|------|
| 底圖 | bank 47 `$AAAC`（PRG `0x5EAAC`，ExRAM `0x5EE6C`） | bank 47 `$A004`（PRG `0x5E004`，ExRAM `0x5E3C4`） |
| 第 c 行第 r 列的格 | tile (2 + 2c, 5 + 2r + (c & 1)) | tile (3 + 2c, 5 + 2r + (c & 1)) |

圖塊表：bank 52 `$A0A8`（PRG `0x680A8`），8 bytes 一筆 `[左上 右上 左下 右下][4 個 ExRAM]`，41 筆。

驗證：先用 `tools/nes_emu.py` 實際玩進一場合戰（劇本 1 織田 → 美濃 墨俣），在戰鬥開始前改 `$79CE` 擷取 48 張野戰畫面緩衝；城地圖則把載入改成 `$A1F5` 並設 `$7D17` bit 1、寬 13 擷取 49 張；兩者和上述規則逐 tile 一致。`verify_battle_maps.py` 再用 `tools/pcode_emu.py` 單獨跑 `$A42F`，97 張的 tile、ExRAM 與畫圖呼叫全部一致。

### 8.4 戰場名（bank 23 `$BC92`，PRG `0x2FC92`）

98 個指標：0–47 是各國野戰地名（例：美濃 = 墨俣），48 空白，49–96 是各國城名（美濃 = 稲葉山、尾張 = 清洲），97 = 安土。

### 8.5 調色盤（bank 21 `$9EA8`，PRG `0x2BEA8`）

三組 BG 調色盤（16 bytes）加一組精靈調色盤。第 0 組是 3 月實際畫面用的；第 1 組把平地的綠改成白（推定為冬），第 2 組只改子調色盤 2（推定為秋）。哪個月用哪組沒追。這張表在野戰模組（bank 21）裡；城地圖沒實際玩到，輸出沿用同一組調色盤（推定）。

## 9. 未解

- 大名記錄大半；茶器的第一個 byte。
- 城地圖地形 1–6 的名稱、第二層的意義；季節調色盤的選法、城地圖實際用的調色盤；組合臉表第 2 個 word。
- 外部資料：找不到 FC 版的能力值資料可對照，所有數值只對照了遊戲畫面（§2.1、§2.4）。
