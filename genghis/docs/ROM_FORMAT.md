# FC 蒼き狼と白き牝鹿・ジンギスカン ROM 格式

KOEI，1988，FC。檔案 `roms/Aoki Ookami to Shiroki Mejika - Genghis Khan (Japan).zip` 內的 `.nes`。

本文的偏移一律是 **PRG 偏移**（檔案偏移減 `0x10`），除非另外寫明。CPU 位址寫成 `$xxxx`。「bank n」指 16 KB 的 PRG bank，PRG 偏移 = `n × 0x4000`。

## 1. 硬體與程式

| 項目 | 內容 |
|------|------|
| iNES 標頭 | `4E 45 53 1A 10 00 12 00`：PRG 256 KB（16 × 16 KB）、沒有 CHR ROM（CHR-RAM）、mapper 1（MMC1）、有電池 |
| 向量 | NMI `$C0D6`、RESET `$C000`、IRQ `$C140` |
| bank 配置 | 和 FC 三國志一樣：`$8000` 可切換，`$C000` 固定 bank 15 |

### 1.1 p-code 直譯器

和 FC 三國志同一代的 KOEI 直譯器。函式開頭 `JSR $EE92`（全 ROM 約 1000 處），opcode 分派表在 `$F695`（低位）／`$F795`（高位）。

| 項目 | 內容 |
|------|------|
| 暫存器 | A = `$08/09`、B = `$0C/0D`、SP = `$02`、FP = `$04`、PC = `$06` |
| frame | 進入時保存 `$00–$07`；呼叫者 PC 在 FP+6、呼叫者 FP 在 FP+4；參數從 FP+`$0B` 起（= 呼叫當下的 SP+2） |
| 原生參數 | `$52` 起 |
| 遠程呼叫 | 跳板在 `$E0C7`／`$E0E3` |

### 1.2 文字

JIS X0201 半形 byte（cp932 解碼後做 NFKC）。`1B 4B`（ESC K）之後是片假名，`1B 48`（ESC H）之後是平假名（把片假名轉成平假名）。字串以 `00` 結尾。畫面上的 tile 碼：平假名 = `0x24 + 五十音序`、片假名 = `0x5E + 五十音序`、濁點 = `0x51`。

## 2. 劇本資料

兩個劇本的初始資料是一整塊 WRAM 映像，開始遊戲時複製到 `$63F0`。兩塊格式相同：

| 劇本 | PRG 偏移（= `$63F0`） | 標頭 `$65BB` | 年 | 部族／國數 |
|------|------|------|------|------|
| モンゴルへん | `0x1C008`（bank 7 `$8008`） | `0E 00 96 04 03 00` | 1175 | 14 |
| せかいへん | `0x1D6B8`（bank 7 `$96B8`） | `1B 00 B5 04 03 00` | 1206 | 27 |

WRAM 位址 → PRG：`PRG = 位址 − 0x63F0 + 基底`。標頭 = 數量（u16）、年 − 1（u16）、`03 00`（未知）。年份已在遊戲畫面確認。

表裡的指標是「映像在 ROM 裡的 CPU 位址」（例如モンゴル的君主 0 = `$81D9`），遊戲載入後改成 WRAM 位址（`$65C1`）。

### 2.1 部族／國名（`$63F0`，17 bytes × 27 格）

只有名稱（§1.2 文字）。

### 2.2 君主（`$65C1`，32 bytes × 27 格）

| 偏移 | 內容 |
|------|------|
| 0–13 | 姓名 |
| 14 | 年齡 |
| 15–26 | 6 個 u16 能力：統率、判断、企画、説得、体力、武力（遊戲畫面的順序：とうそつ、はんだん、きかく、せっとく、たいりょく、ぶりょく） |
| 27 | 未知（都是 2） |
| 28–29 | 頭像碼（§4） |
| 30 | 所屬國編號（= 格序號） |
| 31 | 未知（都是 100） |

玩家可選的君主（テムジン、ジンギスカン）在 ROM 裡能力都是 100／400，開始時「自動決定能力」會重新亂數，所以 ROM 值不是遊戲中的值。

### 2.3 將軍（`$6921`，30 bytes × 20 格）

每個可選君主一家 5 格（格號 ÷ 5 = 家）。モンゴル編只有テムジン一家（カサル、ベルクタイ、カチウン、テムゲ）；世界編 4 家依序是君主 0（モンゴル帝國）、6（イングランド）、10（ビザンツ）、18（日本）。

| 偏移 | 內容 |
|------|------|
| 0–13 | 姓名 |
| 14 | 年齡（畫面確認：カサル 17、ベルクタイ 17、カチウン 15、テムゲ 13） |
| 15–26 | 6 個 u16 能力（同君主） |
| 27 | 未知（0／1／2） |
| 28–29 | 頭像碼 |

### 2.4 未知 8 bytes 表（`$6B97`，8 bytes × 27 格，只有世界編有內容）

每個國一格，兩個劇本都有：`[年齡][u16 數值][u8 0–7][u8 = 1][u8 = 0][u16 頭像碼]`。沒有姓名，頭像都是組合臉。推定是電腦君主的繼承人（數值類似子女表的 u16），未確認。

### 2.5 子女（`$6C6F`，21 bytes × 20 格）

| 偏移 | 內容 |
|------|------|
| 0–13 | 姓名 |
| 14 | 年齡 |
| 15–16 | u16 數值（推定能力；女兒都是 0） |
| 17 | 1 = 男？（女兒都是 0） |
| 18 | 未知 |
| 19–20 | 頭像碼（`0x8000` = 無） |

### 2.6 國（`$6E13`，83 bytes × 27 格）

開頭 20 bytes 是部隊區（推定：本隊＋9 隊 × `[u8 種類 0–2][u8 兵數]`，`FF 00` = 空），後面是 u16 欄位：

| 偏移 | 內容 | 畫面名稱 |
|------|------|------|
| `+0x14` | 武裝度 | ぶそうど |
| `+0x16` | 訓練度 | くんれんど |
| `+0x18` | 兵士數 | へいしすう |
| `+0x1A` | 經濟力 | けいざいりょく |
| `+0x1C` | 町づくり | まちづくり |
| `+0x1E` | 城的強度 | しろのつよさ |
| `+0x20` | 城づくり | しろづくり |
| `+0x22–0x34` | 10 種特產品庫存（畫面只有圖示，沒有名稱；順序 = 畫面左欄由上而下，再右欄） | ざいこ（しょじとくさんひんリスト） |
| `+0x36` | 食糧 | しょくりょう |
| `+0x38` | ROM 是 0，開始後 = `+0x3A` | |
| `+0x3A` | 特產品づくり | とくさんひんづくり |
| `+0x3C` | ROM 是 0，開始後 = `+0x3E` | |
| `+0x3E` | 食糧づくり | しょくりょうづくり |
| `+0x40` | 金 | きん |
| `+0x42` | 民忠（モラル） | モラル |
| `+0x44` | 未知（35／38／40） | |
| `+0x46–0x50` | 未知 bytes | |
| `+0x51–0x52` | 擁有者君主指標：映像的 CPU 位址（モンゴル編 `$81D9` = 君主 0，世界編 `$9889`），每格 32 bytes | |

畫面上「くにデータ」與「ざいこ」的數值和 WRAM 逐一對過（遊戲開始後第一季數值會小幅變動，所以和 ROM 有些不同）。

### 2.7 相鄰表（`$76D4`，12 bytes × 27 格）

`[x u16][y u16][u8 未知][7 個相鄰國編號（0 起算，FF 補）]`。x、y 是大地圖上國旗的畫面 tile 座標（已確認）。モンゴル編的相鄰關係對稱；和戰爭時可選的目標一致。

### 2.8 女性（`0x1EF70`，22 bytes × 40 筆）

前 15 筆是モンゴル編（ボルテ…ぎこくこうしゅ），後 25 筆是世界編（クリスチナ…パイタ）。`[姓名 13][u8 0/1/2][FF 00][3 × u16 專屬頭像編號 21–82]`；3 個編號是同一人的 3 種表情：第 1 張平常，第 2 張多半是笑臉，第 3 張多半是不高興或哭。比對頭像圖得出，哪個場面用哪張尚未確認。編號重複時代表這人沒有那種表情。只有第 2、3 張用到的頭像共 22 張（22, 24, 25, 27, 30, 34, 36, 38, 40, 41, 47, 50, 53, 58, 63, 68, 71, 74, 76, 77, 79, 81），kaodata 匯出只用第 1 張，所以這 22 張沒人用。byte 13 的 0／1／2 和不同表情的張數有關，但不完全對應。

## 3. 大地圖（bank 8）

| 項目 | モンゴル編 | 世界編 |
|------|------|------|
| 名稱表（20 × 16 tile，畫在畫面 tile (10, 4)） | `0x223EC` | `0x2252C` |
| 屬性表（整個畫面 64 bytes） | `0x218CC` | `0x2190C` |
| tile 圖形（pattern table `$1000`，從 tile `0x92` 起） | `0x2194C`（89 tiles） | `0x21EDC`（81 tiles） |
| BG 調色盤（模擬器確認） | `0x22672` | `0x2268F` |

國旗與國號是精靈，位置在相鄰表 x、y；BG 和 `rom.map_pixels()` 逐 pixel 一致（`verify_battle_maps.py`）。

## 4. 頭像

### 4.1 專屬頭像

5 × 6 tiles（40 × 48），每張 480 bytes，83 張（編號 0–82）。指標表 `0x2BCB4`（bank 10 `$BCB4`），每筆 4 bytes `[bank][addr lo][addr hi][0]`：

- 0–33 → bank 11 `0x2C004 + i × 480`
- 34–67 → bank 12 `0x30004 + …`
- 68–82 → bank 10 `0x28234 + …`

君主用 0–20，女性用 21–82。指標第 4 byte 是子調色盤：P70–P79 是 2，其他是 0。

### 4.2 組合臉（頭像碼 bit 15 = 1）

| bits | 欄位 |
|------|------|
| 13–12 | 類型 cat（0–2） |
| 11–9 | 框（頭） |
| 8–6 | 眼 |
| 5–3 | 鼻 |
| 2–0 | 口 |

類型基底表 `0x2BECC`：u16 `[0, 8, 12, 0]`，指標序號 = 基底 + 欄位值。4 張 16 筆 u16 指標表（bank 10 CPU 位址）：框 `0x2BE00`（18 tiles）、眼 `0x2BE20`（3 tiles）、鼻 `0x2BE40`（3 tiles）、口 `0x2BE60`（3 × 2 tiles）。類型 0 用 0–7，類型 1、2 用 0–3。

在 5 × 6 tile 格上的位置：框 18 tiles = 第 0、1 列全部，第 2–5 列的第 0、4 欄；眼 = 第 2 列第 1–3 欄；鼻 = 第 3 列；口 = 第 4–5 列。等於 40 × 48 畫布上眼 (8, 16)、鼻 (8, 24)、口 (8, 32)。

### 4.3 調色盤

頭像畫面的 BG 調色盤 = `0x3FF9E`（bank 15 `$BF9E`）：子調色盤 0 `3E 27 38 30`（黑、橙、淡黃、白），子調色盤 2 `3E 18 28 30`。組合臉都用子調色盤 0。

驗證用的遊戲程式：bank 10 `$80F7(x, y, 頭像碼, flag)`，劇本選單以 `(2, 6, 碼, 4)` 呼叫。把參數換成任意碼，遊戲畫出的 40 × 48 和 `rom.face_pixels()` 一致（168 個碼，`verify_kaodata_export.py`）。

## 5. 戰場地圖

| 項目 | 內容 |
|------|------|
| 地形 | `0x24B30 + idx × 160`，41 張 × 16 欄 × 10 列（idx 0–13 = モンゴル編部族 0–13、14–40 = 世界編國 0–26），到 `0x264D0` 剛好結束。開戰時複製到 WRAM `$615E` |
| 格值 | bit 0–6 = 地形 0–7；bit 7 = 推定為進入格（都在地圖邊緣） |
| 地形 | 0 水、1 砂漠、2 平原、3 森林、4 山、5 町、6 城、7 不可進入（空白）。名稱依圖形推定 |
| 方塊表 | `0x17B9C + 16 × 地形`：4 × 4 tile id |
| 配置 | 每格 4 × 4 tiles；奇數欄往下錯開 2 tile 列；整張 64 × 42 tiles，左右各一個名稱表。地圖第 y 列畫在名稱表第 (y + 4) mod 30 列，垂直捲動時重畫 |
| 屬性 | 每張圖一份：`0x11702 + idx × 176`。前 88 bytes 是左邊名稱表、後 88 bytes 是右邊，各 8 × 11 bytes 的標準屬性格式。第 26–27 列是空的縫：地圖第 26 列以後對應屬性資料的第 y + 2 列（因為第 26 列剛好捲回名稱表第 0 列） |
| tile 圖形 | tile `0x92`–`0xFF`（pattern table `$1000`）= `0x24004` 起 110 tiles |
| BG 調色盤 | `0x24864`：`3E 26 17 30 3E 26 2A 30 3E 2A 39 30 3E 22 38 30` |

模擬器驗證（`verify_battle_maps.py`）：把 41 張圖輪流換進遊戲開戰時讀的位置，WRAM 拷貝、名稱表的 tile 與子調色盤、CHR-RAM、調色盤都和靜態解碼一致；另外確認世界編攻打國 1 時載入圖 15（= 14 + 國號）。

## 6. 驗證

| 項目 | 方法 | 結果 |
|------|------|------|
| 頭像（專屬 83 + 組合臉 85 碼） | 模擬器劇本選單，換掉 `$80F7` 的頭像碼參數，比對畫面 pixel | 168/168 一致 |
| kaodata `genghis-fc` | 參考渲染器 vs ROM 直接組臉，checksums 重算 | 198/198 |
| 大地圖 2 張 | 模擬器進入戰爭目標選擇畫面，比對 BG pixel 與調色盤 | 一致 |
| 戰場地圖 41 張 | 見 §5；每張比對開戰畫面名稱表裡的 30 列（全圖 42 列，其餘在畫面外） | 41/41 一致；世界編圖號對應確認 1 例 |
| 年份、能力值、年齡、國的欄位 | 模擬器遊戲畫面（くにデータ、ざいこ、能力決定畫面）目視比對 | 一致 |

沒有找到可用的外部資料（攻略網站的數值表）可以交叉比對；能力值與國的數值的依據是遊戲畫面。

## 7. 未知

- 君主 +27（都是 2）、+31（都是 100）；將軍 +27（0／1／2）
- 子女 +17（1 = 兒子？）、+18；未知 8 bytes 表的意義
- 國：部隊區的種類 byte、`+0x38`／`+0x3C`（開始後的複製值？）、`+0x44`、`+0x46–0x50`
- 相鄰表 byte 4；女性 byte 13（0／1／2）
- 戰場格 bit 7 的確切意義、地形名稱（依圖形推定）
- 兵種能力、特產品名稱與價格、事件等其他表尚未找
