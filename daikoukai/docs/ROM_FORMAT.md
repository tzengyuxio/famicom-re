# FC 大航海時代 ROM 格式

KOEI，1990，FC。本文件記錄逆向結果；**所有位移都是 PRG 位移**（檔案位移 − 0x10），bank 是 8 KB 的 PRG bank 編號（位移 ÷ 0x2000）。

> 「推定」表示還沒用遊戲畫面或程式確認。

## 1. 硬體與程式

| 項目 | 內容 |
|------|------|
| iNES | mapper 5（MMC5），PRG 512 KB（64 × 8 KB），CHR-ROM 128 KB（128 × 1 KB），電池 |
| PRG 模式 | `$5100 = 3`（4 個 8 KB 槽）；`$E000` 固定 bank 63，`$C000` 通常是 bank 62 |
| CHR 模式 | `$5101 = 3`（1 KB 為單位）；BG 用 ExRAM 擴充屬性（`$5104 = 1`） |
| bank 影子 | zero page `$97–$9B` 對應 `$5113–$5117` |
| 向量 | NMI `$F64C`、RESET `$F500`、IRQ `$FF3E` |
| WRAM | 只用 page 5（`$5113 = 5`），8 KB 存全部遊戲狀態（電池存檔） |

### 1.1 p-code

跟其他 KOEI FC 作品一樣，大部分邏輯是 p-code：函式開頭 `JSR $E4BF`，接 2 bytes frame 大小，再接 bytecode。

| 項目 | 內容 |
|------|------|
| VM 暫存器 | PC `$06/$07`、SP `$02/$03`、FP `$04/$05`；第一個參數在 SP+2 |
| 系統呼叫 | `E9 D4 EE`（呼叫 `$EED4`），**最後推入的值是服務編號** |
| 常見服務 | 2 = 切 bank 呼叫遠端函式（`(1, $C0+bank, 0, 入口)`）、9 = 畫 BG 圖（x、y、w、h、tile 指標、ExRAM 指標、選擇子）、5/C/D = 設 CHR bank 與顯示精靈圖、0x10 = 等待 |
| 常見 opcode | `$60–$6F` 推小常數、`$8D xx` 推 8 位元、`$8C`/`$8E lo hi` 推 16 位元、`$A5 lo hi` 讀全域變數、`$CF` 返回 |

## 2. 文字

單 byte 半形假名（JIS X0201，cp932 的 `$A1–$DF`），以 0 結尾。

- 預設畫成**平假名**；`1B 4B`（ESC K）切成片假名，`1B 48`（ESC H）切回。
- `$DE`／`$DF` 是前一字的濁點／半濁點；`$2D`（`-`）與 `$B0` 是長音 ー。
- `$0A` 換行；`%d`、`%s` 等是 printf 格式。

## 3. 初始遊戲狀態（bank 57）

新遊戲時 bank 57（PRG `0x72000`，8 KB）整塊複製到 WRAM `$6000`，再寫入玩家輸入的姓名、能力與船名。
因此 WRAM 位址 `$6000 + n` 的初始值就是 PRG `0x72000 + n`；以下用 WRAM 位址描述。

姓名等字串放在 bank 58（PRG `0x74000`，以 `$A000` 對應），由 bank 57 裡的指標引用。

| WRAM | 內容 |
|------|------|
| `$6004–$63EF` | 20 個 NPC 艦隊航線區塊（每塊 0x33 bytes：起點、狀態、航線指標、(x, y) 序列，`FF` 結尾） |
| `$6542` | 人物表 41 筆 × 7 bytes，見 §4 |
| `$6662` | 艦隊表（16 bytes／筆），含所在港的 4 bytes 座標組 |
| `$6B1C` | 旗艦名（預設 ヘルメス） |
| `$6BAE` | 主角姓名（預設 レオン） |
| `$6BBE` | 能力表 21 筆 × 10 bytes：主角 + 航海士 20 人，見 §4 |

## 4. 人物

### 4.1 人物表（WRAM `$6542`，41 筆 × 7 bytes）

第 k 筆在 `$6542 + 7k`：0 = 主角（姓名指標 `$6BAE`），1–20 = 航海士，21–40 = 4 國 × 5 名提督。

| byte | 內容 |
|------|------|
| 0–1 | 姓名指標（bank 58，`$A000` 對應；主角指向 WRAM `$6BAE`） |
| 2 | 戰鬥等級 |
| 3 | 航海等級 |
| 4–5 | 頭像代碼（LE16，見 §5） |
| 6 | 旗標：高 4 bit = 國（0 ポルトガル、1 スペイン、2 トルコ、3 イギリス，推定），bit 0 = 有效 |

### 4.2 能力表（WRAM `$6BBE`，21 筆 × 10 bytes）

| byte | 內容 |
|------|------|
| 0 | 年齡（推定） |
| 1–5 | 統率、判断、知力、勇気、強さ |
| 6–9 | 0 |

第 k 筆對應人物 k（0 = 主角，新遊戲時被輸入值覆蓋；1–20 = 航海士）。提督沒有能力表。

外部對照（SNES 版 Uncharted Waters 航海士表，[mikesrpgcenter](https://www.mikesrpgcenter.com/uncharted/mates.html)）：
Fernando（フェルナンド）戰鬥 6／航海 5、Cha 92／Wis 80／Int 75／Cou 80／Str 75，與本表一致；Dias 戰鬥 28／航海 28 一致；英文版 Alfonso = 本版 ファスコ。

### 4.3 女性（公主等）

姓名指標表 PRG `0x7400C`（bank 58 `$A00C`），20 筆；第 k 人頭像 = 專屬頭像 k + 13（bank 1 `$A620` 的分支）。

## 5. 頭像

頭像是**精靈**：30 個 8×8 精靈排成 5 × 6（40×48）。精靈調色盤固定在 PRG `0x7F376`（16 bytes，attr 低 2 bit 選子調色盤，色 0 = 背景 `$0F`）。
全域 `$738C` 是要畫的頭像代碼；bank 1 `$A5B3` 依代碼選 bank 35（專屬）或 bank 36（組合臉，代碼 > `0x0FFF`）。

### 5.1 專屬頭像（代碼 < `0x1000`，48 張）

bank 35（`$8000`）`$9994` 48 個指標；記錄 = 2 bytes CHR bank（`$5120`、`$5121`，1 KB）+ 30 × `(dy, tile, attr, dx)`。

### 5.2 組合臉（代碼 ≥ `0x1000`）

- 頭型 `head = code >> 10 & 3`，CHR bank 取 bank 36 `$8C56` = `[74, 76, 70, 72][head]`（`$5121` = +1）。
- 部件指標表 `$8C5A + 40·head`：5 組（0 上、1 眼、2 鼻、3 口、4 下）× 4 頁指標；每頁精靈數 = (下一頁指標 − 本頁 − 2) / 4。
- 頁碼：上 = `code >> 8 & 3`、下 = `code & 3`、眼 = `>> 6`、鼻 = `>> 4`、口 = `>> 2`。
- 繪製順序 上、下、眼、鼻、口；後畫的精靈若 tile = 1（透明）且該格已有，保留原格。
- 驗證：`verify_kaodata_export.py` 用 p-code 模擬器跑遊戲的繪製函式，比對 OAM（`$0600` 第 33–62 個精靈）。

## 6. 港口

### 6.1 港口表（PRG `0x752D4`，70 筆 × 19 bytes）

15 bytes 名稱 + 4 bytes 座標 `(chunk x, chunk y, metatile x, metatile y)`（座標系見 §7）。

### 6.2 港口屬性（PRG `0x75806`，港 0–49，5 bytes）

| byte | 內容 |
|------|------|
| 0 | 經濟圈 0–7：地中海、北歐、西非、東非、新大陸、阿拉伯、遠東、東南亞（與 mikesrpgcenter 的 [ports](https://www.mikesrpgcenter.com/uncharted/ports.html) 分區一致） |
| 1 | 特產品（goods 編號，`FF` = 無） |
| 2 | 未解（0–7） |
| 3 | 道具店商品（`FF` = 無，推定） |
| 4 | 未解（0–6，與經濟圈大致對應） |

港 50–69 是補給港，沒有屬性記錄。市場行情與產業值在 WRAM `$68E1` 起（初始值 bank 57），格式未解。

## 7. 世界地圖

檔案在 PRG `0x60000`：

| 位移 | 內容 |
|------|------|
| +0 | u16 chunkset 表位移（`0x05A4`）、u16 chunk 資料位移（`0x1552`） |
| +4 | 288 筆 × 5 bytes 區域記錄，區域 = row·24 + col（24 × 12）；bytes 0–1 = chunkset 編號，2–4 未解 |
| +0x5A4 | chunkset：18 bytes = 9 個 LE16 chunk 編號，子位置 `(cy%3)·3 + cx%3` |
| +0x1552 | chunk k 在 +49k：7 × 7 block 編號 |

- block → 4 個 metatile（TL、TR、BL、BR）：PRG `0x3CCA + 4·block`（bank 1 `$BCCA`）。
- metatile 組 s 的第 m 個：PRG `0x3BAA + 0x48·s + 4·m` = (tile 指標, ExRAM 指標)，以 `$A000` 讀 bank 32，各 4 bytes = 2 × 2 tile。
- 組依緯度：`BAND = [3,2,1,1,0,0,0,0,1,1,2,3][cy // 3]`（p-code `$B015`）；調色盤 PRG `0x3A7A + 16·set`。
- 全圖 72 × 36 chunk，每 chunk 28 × 28 tile（14 × 14 metatile），共 2016 × 1008 tile（16128 × 8064 px）。艦隊位置 WRAM `$6662`。
- 港口記號另外蓋在地圖上（tile 56–59、ExRAM `8E`），靜態圖不含。
- 驗證：`verify_maps.py` 從開機重放輸入到出港，航行時每次重畫畫面（svc 9，w = 30、h = 28）比對 WRAM 緩衝與靜態 chunk：chunk (30,9)、(29,9)、(28,9) 皆 784/784 tile 一致。

## 8. 港町圖

- bank 18 `$8032(port)` 回傳類型 0–7：港 0–49 = 經濟圈（屬性 byte 0），港 2 與 12 例外 = 5（阿拉伯式）；港 50–69 查 PRG `0x25338` 的 20 bytes 表。用模擬器跑這個函式，70 港全部與靜態規則一致。
- 圖表 bank 18 `$93CC`（PRG `0x253CC`）：8 × (tile 指標, ExRAM 指標)，28 × 14 tile，畫在 (2, 6)。類型 3、5 在 bank 32，其餘 bank 33（`$A000`）。
- 零件表 PRG `0x2534C`：每類型 4 × (tile, ExRAM) 指標，尺寸 7×4、6×5、6×6、8×5（`$0000` = 無）。
- 建物旗標 WRAM `$6F76 + port`（初始值在 bank 57 `+0xF76`）：交易港在旗標 bit 2 = 0 時於 (2, 6) 畫 7 × 4 零件，bit 4 = 1 時於 (22, 6) 畫 8 × 5 零件（船塢裡的船（推定），里斯本、セビリア、イスタンブール 開局即有）。其他 bit 未解。
- 補給港不看旗標，畫 (9,6)、(2,6)、(2,12) 三塊 7 × 4，加 (16,6) 6 × 5 與 (24,14) 6 × 6，最後 (22,6) 8 × 5 從 RAM 畫（靜態圖不含）。
- 驗證：模擬器以初始旗標跑 `$8032`、`$80CB`，70 港的類型與 svc 9 呼叫全部一致；實機開局的里斯本畫面 392/392 tile 一致。
- 調色盤：svc 6 從 PRG `0x252B8 + 16·type` 讀 BG 16 bytes。
