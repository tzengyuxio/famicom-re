# FC 聖火列傳 ROM 格式

Computer & Entertainment（C&E，台灣，非授權），1991，卡匣編號 A-1061。iNES：PRG 128 KB、CHR-ROM 128 KB、
mapper 240、水平鏡像、flags6 bit 1（PRG-RAM `$6000`）。ROM SHA-1（.nes 全檔）：`7c68ae79d17c940b25f71c170a383246ea042cd3`。

與 KOEI 作品無關，整個遊戲是 6502 原生碼。以下位址寫成「bank N `$xxxx`」＝該 32 KB bank 映射到 `$8000-$FFFF`
時的 CPU 位址（PRG 偏移 = N × 0x8000 + 位址 − 0x8000，見 `Rom.cpu`）。標「推定」者以外都用 `tools/nes_emu.py`
（py65 + mapper 240）跑遊戲本身的程式驗證過。

## Mapper 240

| 位址 | 用途 |
|------|------|
| `$4020-$5FFF` 寫入 | bit 4-7 = 32 KB PRG bank（0-3），bit 0-3 = 8 KB CHR bank（0-15） |

- 寫入值取自各 bank 都有的恆等表 `$F461`（避免 bus conflict）。
- 跨 bank 呼叫走 `$FF24`：`$CB` = bank << 4，A = 函式編號。各 bank 開頭有自己的分派表，例如 bank 1 `$84A3`
  （`LDA $9C; JSR $80AA` 後接 inline 跳躍表）。
- 每個 bank 的 `$FF00` 都是 reset 入口。
- 同一畫面中途會改 `$2000`（例如個人資料畫面上下半用不同 pattern table），截圖要逐掃描線依當時的 `$2000` 畫
  （`Nes.line_ctrl()`、`Nes.screen()`）。

## 文字

**沒有全域字集。** 字形是 2bpp CHR 中的 1bpp 字：每個 16×16 格（4 個 tile）的 plane 0 與 plane 1 各放一個字，
由調色盤決定顯示哪一個：子調色盤 `0E 20 0E 20` 顯示 plane 0，`0E 0E 20 20` 顯示 plane 1。

字碼 c：格 = `c & 0x3F`（tile `4n .. 4n+3`，排成 `[[T, T+1], [T+2, T+3]]`，pattern table `$0000`），
bit 7 = plane（遊戲用屬性表選子調色盤）。字碼指向的是**當時載入的 CHR bank**（`$8C`）裡的字型頁，所以同一個
字碼在不同 CHR bank 是不同的字。

字串表（bank 3）：

- 文字副程式 bank 3 `$AD98`：`table = word($AE7F + 2 × $14)`，`str = word(table + 2 × $13)`，字串以 `FF` 結尾。
- 20 組（`$14` = 0-19）。每組第 0 筆是 1 byte 的組頭（不是文字）。
- 對話由呼叫端設定 `$14`、`$13` 與字型 `$8C`（例：bank 0 `$C615` 由 `$C6F7[$C0AD[$05E8]]` 取組）。
- 選單多半不是字串，是預先排好的 tile 畫面（bank 2 `$80CE` 的 RLE 畫面；bank 0 `$968E` 複製視窗）。

已轉寫（`text.py`，`export.py` 輸出 `font00.csv`／`font09.csv` 與 `text/group00.png`／`group09.png`）：

| 組 | 字型 | 筆數 | 內容 |
|----|------|------|------|
| 0 | CHR bank 0 | 84 | 1-19 武器、20-28 消耗品、29-41 人物名（id + `$1D`，bank 0 `$CB15`）、42-69 武功、70-83 戰鬥用詞 |
| 9 | CHR bank 9 | 76 | 1-60 敵人名（含劇情對手、各派人物）、61-75 戰鬥訊息（迎戰／勝利／Gold+／Exp+） |

轉寫是看字形圖逐字判讀；`charmap` 檢查同一字碼在所有字串都轉成同一字（108 + 119 個字碼，無矛盾）。
低解析度不確定的字：`棈`（楊棈，木＋青；也可能是「楨」的簡筆）、`蠶`（黃蠶／金蠶）。

**未解：** 其餘 18 組（對話、劇情、商店、選單說明）的字型 CHR bank 與轉寫。各組的 CHR bank 要從呼叫端
（設定 `$14` 與 `$8C` 的程式）逐一追出。

## 人物（bank 0）

RAM 是 struct-of-arrays，**以隊伍欄位為索引**（13 欄；隊伍成員 id 清單在 `$03A8`，`FF` 結尾）：

| RAM | 內容 |
|-----|------|
| `$0507` | 等級 |
| `$0514` | 力量 |
| `$0521` | 敏捷 |
| `$0555` | 裝備武器（group 0 字串號 1-19；0 = 無） |
| `$0562` / `$056F` | MP / 最大 MP |
| `$057C` / `$0589` | HP / 最大 HP |
| `$0596-$059E` | 主角經驗值，9 位十進位 |
| `$0412` / `$03F4` | 道具欄：道具號、數量（`FF` 結尾） |

數值都是二進位，畫面顯示時轉十進位。`$052E`/`$053B`/`$0548` 在 bank 0 `$B99F` 由等級／力量／敏捷的高低 nibble
互換組成，用途不明（新遊戲時畫面上的 ATT/DEF/ACC 分別等於力量、敏捷、等級，與這三格不同；推定）。`$05E9-$0630` 是音效引擎。

人物 id 0-12，id 4 = 少主（玩家）。

**章節初始能力**：bank 0 `$C311` 依 `$7C`（章 0-4）跳到 `$C31B`／`$C358`／`$C395`／`$C3D2`／`$C40F`，從
`$9077`／`$90D2`／`$912D`／`$9188`／`$91E3` 各 7 張 13 byte 的表（等級、力量、敏捷、HP、最大 HP、MP、最大 MP，
以人物 id 為索引）寫入隊伍欄位；主角（id 4）略過。HP 寫入只在 `$07E7` bit 7 = 0 時，MP 只在 `$07E7` = 0 或負時。
第 5 章另有特例：`$E9 == $F8` 時 id 8 與 id 10 改用 `$A0A4`／`$A0A9` 的 5 byte。

**武功**：`$924B`（13 byte）= 每人的清單偏移；`$9258 + 偏移` = 習得等級清單、`$9282 + 偏移` = 武功（group 0
字串號）清單，兩者都 `FF` 結尾、一一對應。個人資料畫面「武技」欄就是這兩張表（例：少主 天心劍法 L15、霹靂槍法 L17）。
`$923E`（13 byte，只有 id 2 = 2、id 11 = 1）用途不明。

## 頭像

精靈記錄表 bank 0 `$EAB3`（LE16 指標）：記錄 0-90 是 7 byte 的 2×2 精靈；記錄 `$5B + id`（91-126）是頭像：
`[w = 4, h = 5, 子調色盤, 20 個 tile（逐列）]`，tile 在 pattern table `$1000`。

| 畫面 | 程式 | CHR bank | 調色盤 | 繪法 |
|------|------|----------|--------|------|
| 個人資料／隊伍總表 | bank 0 `$B9E1` → `$E817`（`$66` = id + `$5B`） | 0 | `$E737` 精靈調色盤，子調色盤 = 記錄 byte 2 | 精靈 |
| 對話 | bank 0 `$C4CE`（`$E3` = 說話者 id） | `$C5E8[id]`（0-12 → 0、13-24 → 4、25-35 → 5） | `$E777` BG；`$C547[id]` = 0 → 屬性 `$AA`（子調色盤 2），否則 3 | BG tile，畫在 `$208E` |

36 張頭像：0-12 是隊伍成員（姓名見人物表），13-35 是其他說話者（姓名要從對話轉寫，**未解**）。
記錄 127（id 36）表頭是 `[5, 9, 0]`，內容是 5 欄的精靈排列，不是頭像；對話程式不看表頭、硬取 20 byte，所以若以
36 叫用會畫出亂碼。

## 地圖（bank 1；屬性在 bank 3）

| 位址 | 內容 |
|------|------|
| bank 1 `$8671` | 24 個 LE16 指標 → 地圖資料 |
| bank 1 `$84D9` | 24 byte：畫面高度 − 1 |
| bank 1 `$84F1` | 96 個 metatile：`[左上, 右上, 左下, 右下]` tile 號（CHR bank 1，pattern table `$0000`） |
| bank 1 `$F361` | 96 byte：每個 metatile 的地形類別 |
| bank 3 `$8230` | 24 個 LE16 指標 → 每畫面 64 byte 屬性表（地圖 21-23 共用 `$8260`） |
| bank 0 `$E797` | 32 byte 調色盤（BG + 精靈），所有地圖共用（`$8312` 上傳） |

- 地圖資料不壓縮：每個畫面 240 byte = 16 × 15 個 metatile（逐列）；畫面**逐欄**存放（垂直相鄰 = +1 畫面，
  水平相鄰 = +高度 畫面）。畫面數從指標間距得出：
  `[54, 4, 2, 1, 2, 2, 2, 4, 2, 1, 1, 1, 1, 4, 1, 4, 4, 4, 1, 2, 1, 6, 6, 6]`。
- 屬性表就是 PPU 的 64 byte 格式：cell (r, c) 的子調色盤 = `byte[(r // 2) × 8 + c // 2] >> (((r & 1) << 2) | ((c & 1) << 1)) & 3`。
- 遊戲的畫圖程式：列 bank 1 `$8192`、欄 bank 1 `$80BF`（輸出 `$0700`，30 tile）、屬性 bank 3 `$8000`
  （輸出 `$0310`），NMI 上傳 bank 1 `$827C`／`$82C8`。`$9E` bit 7 = 用 `$9D` 號地圖，否則大地圖。
- **大地圖**（地圖 0）9 × 6 畫面 = 144 × 90 格 = 2304 × 1440 px，是一整張，不分區。其餘地圖都是由大地圖入口
  進入的獨立小地圖，沒有和大地圖相接的邊，所以不需要拼接。

地形類別（處理程式跳躍表 bank 0 `$8886`）：

| 值 | 意義 | metatile |
|----|------|----------|
| 0 | 可通行 | |
| 2 | 不可通行 | |
| 3 | 地圖入口：所在大地圖畫面在 bank 0 `$88AC`（20 byte）的第 i 筆 → 進地圖 i + 1（`$8896`，`STX $9D` 於 `$88A4`） | 78 |
| 4 | 城鎮：所在畫面（`$A2`）在 bank 0 `$891E`（8 byte，第 0 筆不用）的第 i 筆 → 城鎮 i（`$88ED`） | 14 |
| 5 | 事件 | 12、54 |
| 6 | 下一層（`INC $9D`，`$8974`） | 73 |
| 7 | 上一層（`DEC $9D`，`$8983`） | 72 |

大地圖共 27 個入口：20 個地圖入口（M1-M20）、7 個城鎮（T1-T7），見 `entrances.csv` 與
`maps/world_labelled.png`。地圖 21-23（`$9D` = `$15-$17`）是地圖 1 的後期版本：`$9D == 1` 且 `$05E7 & $40`
時於 `$88D7` 改進，起點取自 `$F704`。地圖 1、7、8、13、15、17 內也有類別 4 的格子（城鎮內的出口，推定）。

**驗證**（`verify_maps.py`）：開新遊戲，大地圖起始畫面與經由遊戲進入程式（`$88A4`）進入的地圖 1-20，可見名稱表
（tile 與屬性，套用捲動）必須等於解碼結果某個位置（各 160/160）；再對 24 張地圖每個畫面每一欄，叫用遊戲的欄
建構與屬性建構程式，3712 欄全部與解碼一致。

**未解：** 城鎮內部的畫面（進城後是對話／選單，推定沒有可走的城鎮地圖）、事件格對應的事件內容、各地圖名稱。

## 戰鬥與遇敵（bank 2；遇敵在 bank 0）

- **遇敵**：bank 0 `$D2C4`：列 = min(隊伍第 1 人等級, 10) − 1，從 `$D308` 的該列（4 組 × 2 byte）隨機取一組
  （左隊、右隊的敵人種類，寫到 `$05E5`／`$05E6`）；再以 1/32 機率改從前 32 組（等級 1-8 的列）中隨機取一組。
  戰鬥開始時 bank 2 `$9AD8` 把兩種各放兩隻（`$077C-$077F`）。
- **敵人表**：bank 2 `$CF21` 起 5 張 30 byte 的表（以種類為索引），bank 2 `$B986` 複製到 `$0780`／`$0784`／
  `$0788`／`$078C`／`$0790`：

  | 表 | 欄 | 用途 |
  |----|----|------|
  | `$CF21` | stat0 | 命中判定 `$BEE3` 中與我方值相減（推定為等級／防禦類） |
  | `$CF3F` | HP | 已用戰鬥畫面確認（山大王 130、御林軍 100） |
  | `$CF5D` | stat2 | 不明（推定攻擊力） |
  | `$CF7B` | stat3 | 1-5，`$B352` 從我方值中扣除（推定） |
  | `$CF99` | speed | 寫入行動順序排序鍵 `$0318`（`$BBD7`） |

- **敵人名**：bank 2 `$B791[種類]` = group 9 字串號（bank 2 `$9BA6`）。種類 5（血蛤）全部為 0，推定未使用。
- `$0760` = 本回合的行動（group 0 字串號：1-19 武器、20-28 道具、42-69 武功）。bank 2 `$ABA3`（28 byte）
  為道具 1-28 寫入 `$07BB` 的值（刀劍 0、斧棍 12、槍鏢 4、彈 4），之後呼叫命中判定 `$BEE3`；意義不明。

**未解：** 武器攻擊力（裝備武器不改變個人資料的 ATT）、武功的 MP 消耗與威力、勝利獎勵（Gold／Exp）、
劇情戰（group 9 的 36-60 號對手不在 30 種的敵人表中）、商店品項與價格。
