# 天地を喰らう（FC）ROM 格式

iNES：mapper 1（MMC1），PRG 256 KB（16 bank × 16 KB），CHR-RAM 8 KB，有電池（WRAM $6000–$7FFF）。
下文「bank N $XXXX」指把 bank N 切到 $8000 時的 CPU 位址；bank 15 固定在 $C000。

## 1. 程式架構

- bank 切換：`$C482`（A = bank），`$C49E`／`$C4A2`／`$C4A6` 分別切 12／13／14，`$C47E` 切回 `$43` 記的 bank
- `$C4E4`／`$C4FB`：跨 bank 呼叫的小技巧，`$C4FB` 讀呼叫點後 2 byte 當返回位址
- `$DD14`：把呼叫點後的位元組當參數讀（inline 參數）
- `$C000`：協作式多工排程器。每個 task 在 `$20+4n` 存狀態、`$22+4n` 存自己的 SP；`$C09F` 讓出 CPU 等 NMI（因此在模擬器裡「直接呼叫」會等 NMI 的副程式要跑整個 frame，見 `tools/emu.py` 的 `call_frames`）

## 2. 文字

### 2.1 字型與編碼

選單／對話字型是 pattern table $1000 的 tile $00–$7F（見 `rom.py` 的 `FONT`）：

| 碼 | 意義 |
|----|------|
| $00–$7F | 字型 tile（數字、平假名、片假名一部分、記號、`金`、`兵`） |
| $80–$E1 | tile (c & $7F)，上一行加濁點 tile $72 |
| $E2–$EE | tile (c & $7F) − 10，上一行加半濁點 tile $73 |
| $EF–$FF | 控制碼 |

一行文字分上下兩列輸出（上列 $0300、下列 $0318），濁點放上列。

### 2.2 控制碼（`$D250`）

| 碼 | 參數 | 意義 |
|----|------|------|
| EF n | 1 | 地名：區域 n 的名稱（bank 12 $A100+n／$A140+n 指標） |
| F0 n | 1 | 詞典第 n 詞（bank 13 $B700／$B800 指標，FE／FF 結尾，可再含控制碼） |
| F1 n | 1 | 道具 n 的名稱 |
| F2 n | 1 | 武將 n 的名字 |
| F3 | – | 道具名（變數 `$4D`） |
| F4／F5／F6 | – | 人名（變數，`$D49A`／`$D49F`／`$D496`，意義未逐一確認） |
| F7 | – | 事件對象武將的名字（`$05F0+$72`） |
| F8 lo hi | 2 | 呼叫 hi:lo 的程式（hi bit 7 清除時切 bank 13） |
| F9 | – | 未解（出現在選項前） |
| FA／FC | – | 換行 |
| FB | – | 等按鍵 |
| FD | – | 換頁 |
| FE／FF | – | 結束 |

### 2.3 台詞

bank 10 與 bank 11 各有 512 個指標：低位元組 $8000+i、高位元組 $8200+i，字串 FF 結尾。指向 $8400 以下的是空項。共 886 段（`messages.csv`）。哪個事件用哪段台詞屬於事件腳本，尚未解。

## 3. 武將（bank 12）

指標：$A800+id（低）、$A900+id（高），id 0–216 有效（217 以後指向填充區）。同一人常有多個 id（例：リュウビ 166–168、リョフ 181–183／188／192／196），各 id 的數值可能不同（不同時期登場）。

| 位移 | 內容 |
|------|------|
| +0 | ぶりょく（狀態畫面確認） |
| +1 | ちりょく（狀態畫面確認） |
| +2 | 遇敵區域：隨機戰鬥時與 `$6026` 比對（§6.2） |
| +3 | 未解 |
| +4 | 低 5 bit＝敵方武器類別（攻擊力查 bank 14 $8602），高 3 bit 未解 |
| +5 | 敵方鎧（查 $E6D1 → 武裝度） |
| +6 | 敵方兵士階級（0＝依區域用 $E3AC 的雜兵值） |
| +7 | 兵士階級：bit 7 清除→查 bank 12 $BED0 的 word 表；bit 7 設定→隨等級成長（§3.2） |
| +8 | 敵方等級（策略用） |
| +9 | すばやさ（`$61B4`，決定出手順序；裝備道具 $21 時 ×1.5；$E78C 列出的 id 依等級調整） |
| +10–15 | 頭像 6 個 chunk（§3.1） |
| +16 | 低 4 bit＝頭像配色（0＝沒有頭像），高 3 bit＝第 1–3 個漢字在 bank 2（否則 bank 1） |
| +17–19 | 漢字碼，FF 結尾 |
| +20– | 名字（片假名），FE／FF 結尾 |

### 3.1 頭像與漢字名

- 頭像 48×48 = 6×6 tile，逐列排。chunk 值 v：bank 2（v bit 7 設定時 bank 3）$8800 + (v & $7F) × $60 的 6 個 2bpp tile。載入程式 `$CFA9`
- 調色盤：BG 第 3 組 = [$0F, $37, $26, X]，X = $D0FD[配色]（$21, $11, $1A, $14, $00, $15, $17, $18, $20）。配色 0 時 3 色全設 $0F（全黑），9 個 id（雜兵、孫策）因此沒有頭像
- 漢字：每字 16×16、1bpp、32 byte，位於 bank 1／2 的 $8000 + 碼 × 32，tile 順序左上、左下、右上、右下，寫到 plane 1。選 bank 的程式 `$D4C9`：每個漢字獨立看 +16 的 bit 7／6／5（不是累加）
- 漢字碼沒有 Unicode 對照表；CSV 只給碼，字形見 PNG
- **橫條拼貼**：頭像沒有像 KOEI 大眾臉那樣的算式，每人紀錄直接寫 6 個 48×8 橫條碼，所以「拼法」就是共用橫條。208 個有頭像的 id 只有 132 種橫條組合（45 種另配了不同配色）；106 種至少和別人共用一條，6 條全是自己的只有 26 種（例：チョウカク `FA–FF`）。256 個碼全部用到，幾乎都固定在同一個位置（只有 4 個碼出現在 2–3 個位置），共用最多的是 `B3`、`C4`（各 18 張臉）。ソウソウ（112）與カンコウ（172）連配色都一樣，只有漢字名不同。統計與總覽見 `export.py` 的 `portrait_strips.csv`、`strips_sheet.png`

### 3.2 兵士數

- 固定：bank 12 $BED0 + 階級 × 2（word），129 階，階級 1 = 100，每階約 +5%
- 成長（+7 bit 7，`$B4E0`）：Lv1 = 100；每升 1 級 ×(256 + rate)/256（取整，只保留 16 bit），rate = bank 14 $B569[(+7 & $7F) + k]，k 在 Lv10／20／30／40 各 +1（$B582）；Lv50 以後每級 +2000
- 隊伍：`$60A8+slot` = id，`$60D0`／`$6160` = 目前／最大兵士數（每人 4 byte），`$619C` ぶりょく、`$61A8` ちりょく、`$61B4` すばやさ，等級 `$6073`
- SP = ちりょく × `$61F8` / 256 − `$61FE`，存在 `$61FB`；軍師的ちりょく < ぶりょく 時為 0

## 4. 道具與商店

- 道具：bank 12 指標 $A3C8+id／$A438+id，0–$6F；紀錄 = 價格（word）+ 名稱（FF 結尾）
- 武器 $40–$52：類別 = id − $3F，攻擊力 = bank 14 $8602[類別]
- 鎧／兜 $58–$6F：武裝度 = $E6D1[id − $58]。同名的兩個 id 裡實際用到的是商店有賣的那個（鎧是奇數 id，兜是 $68–$6F）
- 道具欄：`$6100 + slot × 8`，bit 7 = 已裝備
- 商店：bank 14 指標 $905D+n／$9085+n，FF 結尾的道具 id 列表。有效的是 0–36（37 以後指到程式）
- 城鎮 → 商店（`$8F94`）：Y = 目前區域（`$6012+$6011`），區塊欄 `$63` < 7 用 $8F9D+Y（左側店），否則 $8FDD+Y（右側店）。$71–$7E 帶的是預設值 0／1（楼桑村的店），這些區域沒有店

## 5. 策略（id 1–30）

名稱：bank 12 $A700+id／$A720+id。其餘都在 bank 14，以 id 為索引：

| 表 | 內容 |
|----|------|
| $B884[等級] | 該等級習得的策略 id（等級 2–31） |
| $B8B6 | 系統（0 火、1 水、2 回復、3 防禦類、4 妨害類、5 特殊攻擊） |
| $B8D5 | 系統內的等級 1–5 |
| $B8F4 | 必要ちりょく |
| $BB40 | 單體對象（$80 敵、$01 我方） |
| $BB5F | 全體對象（同上） |
| $BB7E | 屬性（1 火、2 水） |
| $BB9D | 威力 |
| $BBBC | 未解（只有部分高級策略非 0） |
| $BBDB | 消耗 SP |
| $BBFA | $80 = 移動中可用 |

## 6. 戰鬥編成

### 6.1 固定戰鬥

bank 12 $8D60 + n × 5：5 個武將 id（0 = 空），n = 0–79。`$75` ≥ 0 時用第 `$75` 組。

### 6.2 隨機遇敵（bank 14 `$9BEA`／`$B324`／`$B40E`）

- 只在大地圖（區域 0、區域堆疊深度 0）、地形 ≥ 2 的格子上觸發（`$F4C9`）
- 區域 `$6026`：bank 13 $BE98 + (區塊列 − 4) × 12 + 區塊欄 / 2 的 nibble（偶數欄取高 4 bit），區塊列 4–23、欄 0–23；0 = 不遇敵
- 人數：$B3FE[亂數 & 15]（2–5 人）
- 雜兵種類：檢查周圍 9 格地形（`$D733`）：有 $10 → 1 カイゾク，有 $04／$14 → 2 サンゾク，都沒有 → 3 トウゾク／4 へイシ 隨機；區域 ≥ 6 一律 4 へイシ
- 每一格：區域 ≥ 6 時 1/2、否則 3/4 機率放雜兵；名單空了也放雜兵，而且之後的格子都放雜兵
- 放武將時：從 id 1–$E0 中挑 `$6300+id` bit 4 設定、且紀錄 +2 = `$6026` 的人（`$B43B`）隨機一位，挑中後清掉 bit 4（同一場不重複）
- 收尾（`$B3CA`）：領頭（第 1 格）是武將時，從頭把連續的武將的 bit 4 還原，遇到第一個雜兵起，之後非空的格子都改成 4 へイシ；領頭是雜兵時不做任何事（挑中的武將 bit 4 保持清除，何時還原未確認）
- `$6300+id`：新遊戲時 bank 13 $98C7 的 bit 表（每 id 1 bit，MSB 先）設成 $98，其餘 $80；事件用 `$E397` 加入名單（呼叫點後接 FF 結尾的 id 列表，例：bank 13 $A30E、$B423）
- 特例（`$B40E`）：`$639D`（龐統 157）= $98 且區域 5 → 固定戰鬥 75；`$63B7`（呂布 183）bit 7 設定且區域 6 → 固定戰鬥 79

## 7. 地圖

### 7.1 區塊格

- 整個世界是一張 50 列 × 32 欄的區塊格：bank 9 $A700 + 列 × 64 + 欄 × 2 = (區塊 index, bank)。bank 是 5／6／7／$0C；$0C 且 `$6570[index]` 非 0 時改用 $0D（事件改變地形）
- 一個區塊 = 一個畫面 = 16 欄 × 15 列 metatile（16×16 px）。區塊資料 72 byte，在該 bank $8000 + index × 72：前 64 byte = 8×8 個 chunk id，後 8 byte 是遮罩，第 r 個 byte 的 bit (0x80 >> c) 設定時 chunk id + 256。8×8 chunk 有 16 列 metatile，第 16 列（row 15）不顯示也走不到
- chunk = 2×2 metatile [左上, 右上, 左下, 右下]，bank 9 page CHUNK_PAGE[tileset]（$80／$8D／$9A）+ id × 4
- metatile：bank 9 page METATILE_PAGE[tileset]（$88／$95／$A2）起連續 5 頁，分別是左上、右上、左下、右下 tile 號與屬性（bit 0–1 = 調色盤）
- 地形：bank 9 page $B7 + tileset。0 = 可走不遇敵，2 = 平地／道路，3 = 森林，$0E／$0F = 出口，$10 = 水（大地圖），$14–$16 = 不可走
- 查格子的程式 `$D83E`：輸入 `$1C` 區塊內列、`$1D` 區塊列、`$1E` 區塊內欄、`$1F` 區塊欄、`$48` tileset，回傳 Y = metatile；metatile 1 是寶箱，已開過的回傳 2
- 位置：`$60` 區塊內列（0–14）、`$61` 區塊列、`$62` 區塊內欄、`$63` 區塊欄

### 7.2 區域與圖像

- 區域 `$47` = `$6012+$6011`（`$6011` 堆疊深度，進入時把位置存在 `$6016+`）
- 區域類型：bank 14 $BF98 + area/2 的 nibble（奇數取低 4 bit）。tileset = 0（類型 0）、1（類型 1–3）、2（類型 4 以上）
- BG CHR tile $80–$FF：bank 4 + 類型 × $800 的 2 KB。水面等動畫 tile 執行時另外覆寫
- BG 調色盤：bank 15 $C6B2／$C6C2[類型] 指向封包（第 1 byte = 起始 index，接著顏色直到 ≥ $80）
- 區域名：bank 12 $A140+(area − $40)／$A180+(area − $40)，$52–$7F 有名稱

### 7.3 出入口、傳送點、寶箱

- 出入口：bank 7 $8000+i／$8100+i 指標，240 筆，每筆 9 byte：[方向 << 6 | 區塊內列, 區塊列, 區塊內欄, 區塊欄, 目的區塊內列, 目的區塊列, 目的區塊內欄, 目的區塊欄, 目的區域]；踩上去把目前區域推進堆疊
- 傳送點（同層移動）：bank 7 $8200+i／$82B0+i，176 筆，格式同上（第 5 byte 高 4 bit 是旗標）
- 寶箱：bank 12 $8800+area／$8880+area 指標，每筆 5 byte [區塊內列, 區塊列, 區塊內欄, 區塊欄, 道具 id]；一區的寶箱到下一區的指標為止（程式最多看 8 筆）。開過的旗標：`$6600+area` 的 bit (0x80 >> n)
- 大地圖事件觸發：bank 12 $8C00（4 個陣列 × $58），內容未解

### 7.4 區塊屬於哪個區域

ROM 裡沒有「區塊 → 區域」的表：所有區域共用同一張區塊格，只靠出入口把玩家送到不同位置，再用該區域的類型選 tileset。`export.py` 的區域圖用「離哪個區域的抵達點（出入口／傳送點目的地）最近（40 格內）」推定，邊界可能不準，不屬於該區域的區塊會調暗。大地圖（區域 0）取區塊列 4–23、欄 4–23。
