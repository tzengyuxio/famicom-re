# FC ファミコントップマネジメント 解析

KOEI，1990-12-12，FC（MMC1，PRG 256K，CHR-RAM）。經營模擬：玩家當 5 家電腦公司之一的社長，從 1995 年 4 月開始經營ホビー（個人電腦）／ブック（筆記型）／スーパー（超級電腦）三種產品。ROM 結構與各表格式見 [docs/ROM_FORMAT.md](docs/ROM_FORMAT.md)。

遊戲沒有人物頭像（社長只有名字），所以不做 kaodata 匯出；部門畫面的人物插圖等以 PNG 輸出。

## 指令

```bash
# 公司、需求曲線、廣告費曲線、插圖、訊息文字 → topman/output/
.venv/bin/python topman/export.py [--rom ROM] [--out DIR]

# 模擬器驗證（需 py65，約 1 分鐘）：從開機玩一局 1 人新遊戲，比對公司資料、曲線與畫面上的插圖
.venv/bin/python topman/verify.py
```

ROM 預設直接讀 `roms/Famicom Top Management (Japan).zip`（`--rom` 也接受 .nes 或 .zip）。依賴：Pillow、openpyxl；py65（驗證用）。

## 檔案

| 檔案 | 用途 |
|------|------|
| `rom.py` | ROM 解碼：文字（含自訂片假名碼）、新遊戲 WRAM 映像（5 家公司與各部門紀錄）、需求／廣告費曲線池、插圖描述表與調色盤、訊息字串 |
| `export.py` | 匯出 CSV（UTF-8-BOM）／XLSX／PNG |
| `verify.py` | 模擬器驗證 |
| `tools/emu.py` | 沿用 `sangokushi/tools/nes_emu.py`（MMC1＋py65），加上按鍵腳本與畫面（背景＋sprite）渲染 |

## 輸出

| 檔案 | 內容 |
|------|------|
| `companies.csv` | 5 家公司：名稱、社長、資金、各部門人數（総務／開発 3 產品／製造 3 產品／営業 3 產品）、給料、ボーナス、能力、モラル、3 產品性能、生產線數與分配、庫存、生產性、價格、ブランド、ノルマ、未知欄位原值、附加區塊（hex）與 WRAM 指標 |
| `demand_curves.csv` | 3 產品 × 5 條需求曲線 × 35 年（1990–2024），值已 ×40 換成台數；新遊戲每產品亂數選 1 條 |
| `ad_curves.csv` | 3 媒體（ざっし／しんぶん／テレビ）× 5 條 × 12 個值；新遊戲每媒體亂數選 1 條 |
| `pictures.csv`、`pictures/<類別>_<nn>.png` | 65 張插圖：年初會議室、月初主畫面 4 季、部門人物 8 張、テレビよこはま新聞圖 24 張、標題、KOEI logo、排名頒獎台、公司 logo 等；記錄描述表位置、寬度來源、調色盤（verified／guessed／unknown→灰階）與版面是否已解 |
| `strings.csv` | 853 段訊息文字（PRG 位移、bank）；`%s`、`%d` 是格式碼。bank 10 有各指令的說明文字（攻略用） |
| `topman.xlsx` | 以上各表 |

## 驗證結果（`verify.py`）

- 5 家公司的紀錄（主紀錄＋総務／開発／製造／営業 4 個子紀錄＋附加區塊）與遊戲開始後的 WRAM 一致；不同處只有玩家輸入的社長名、玩家公司的 +0x0E–0x15（4 個 word）、附加區塊第 0 byte（開局設成 20）
- 3 條需求曲線、3 條廣告費曲線都在各自的池裡（需求這幾次都選到第 2 條）
- 年初會議室、月初主畫面（春）、6 個部門畫面的人物插圖都與畫面逐 pixel 一致（調色盤取自 ROM）。部門畫面出現哪個人物每局不同，但每張人物圖固定配自己的調色盤
- 另手動比對：新聞畫面 18 號圖與畫面一致

## 進度

- ✓ MMC1 bank 配置、p-code 呼叫慣例、文字編碼（JIS 假名顯示為平假名＋自訂片假名／少數漢字碼）
- ✓ 新遊戲 WRAM 映像：5 家公司與 4 個部門子紀錄的主要欄位（對過遊戲畫面）

- ✓ 插圖描述表格式、部門調色盤；會議室／季節／部門人物以模擬器驗證
